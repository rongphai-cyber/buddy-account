# ย้ายลูกค้ารายใหญ่ไปเซิร์ฟเวอร์/ฐานข้อมูลแยก (T0.18)

ลูกค้ารายใหญ่บางรายต้องการฐานข้อมูลหรือเครื่องแม่ข่ายของตัวเอง เช่น ด้วยเหตุผลด้านความปลอดภัย ความเร็ว หรือต้องการเก็บข้อมูลไว้ในบริษัท

**แนวทางที่เลือก:** ติดตั้ง Buddy Account อีกชุดหนึ่งให้ลูกค้ารายนั้น (โปรแกรมเดียวกัน แต่ใช้ฐานข้อมูลของตัวเอง) แล้วย้ายข้อมูลของลูกค้าทั้งรายไปด้วยแฟ้ม `.buddy-tenant`
- ไม่ต้องแก้โค้ดส่วนอื่น เพราะลูกค้าแต่ละรายแยกกันด้วยตัวกรองอยู่แล้ว
- ไม่ต้องทำระบบเลือกฐานข้อมูลตามลูกค้าภายในเครื่องเดียว ซึ่งเสี่ยงและซับซ้อนกว่ามาก

## สิ่งที่ย้ายไปด้วย

| ย้าย | หมายเหตุ |
|---|---|
| ลูกค้าผู้ใช้บริการ, กลุ่มผู้ใช้, ผู้ใช้ | รหัสผู้ใช้ รหัสผ่าน และยืนยันตัวตนสองขั้น (2FA) ใช้ของเดิมได้ |
| ทุกบริษัท และทุกตารางของบริษัท | รวมเอกสาร ใบสำคัญ แฟ้มหลัก ภาษี ค่าตั้งค่า สิทธิ์รายเมนู แบบฟอร์ม กุญแจ API และกุญแจ AI |
| แฟ้มบันทึกเหตุการณ์ของลูกค้ารายนั้น | ต่อท้ายในเครื่องใหม่ตามลำดับเดิม |
| ไม่ย้าย | การเข้าระบบที่ค้างอยู่ และคิวซิงก์ของเครื่องออฟไลน์ (ซิงก์ใหม่กับเครื่องใหม่) |

- **ค่าลับ:** กุญแจ 2FA และกุญแจ AI เข้ารหัสด้วยกุญแจของแต่ละเครื่อง ระบบถอดรหัสตอนส่งออกแล้วเข้ารหัสใหม่ด้วยกุญแจของเครื่องใหม่
- **ผู้บันทึกที่ไม่ใช่ผู้ใช้ของลูกค้า:** ข้อมูลที่เจ้าหน้าที่ผู้ให้บริการเคยบันทึก จะมีช่อง "ผู้บันทึก" ว่างที่เครื่องใหม่ เพราะผู้ใช้ของผู้ให้บริการไม่ได้ย้ายไปด้วย
- **สิทธิ์รายเมนู:** จับคู่ด้วยรหัสเมนู (รหัสภายในของเมนูต่างกันในแต่ละฐานข้อมูล)
- **ความปลอดภัยของแฟ้ม:** แฟ้มเข้ารหัสทั้งแฟ้มด้วยรหัสผ่านที่ตั้งตอนส่งออก (AES-256-GCM, scrypt, อย่างน้อย 12 ตัว)
  - แฟ้มมีข้อมูลส่วนบุคคลทั้งหมดของลูกค้า ให้ส่งรหัสผ่านแยกจากแฟ้ม
  - ลบแฟ้มทิ้งเมื่อย้ายเสร็จ

## ขั้นตอน

1. **ติดตั้งเครื่องใหม่:** ใช้ตัวติดตั้ง Windows (T7.4) หรือเซิร์ฟเวอร์ที่มี PostgreSQL ของตัวเอง
   - ต้องเป็น**โปรแกรมรุ่นเดียวกัน**กับเครื่องเดิม ระบบตรวจรุ่นโครงสร้างข้อมูลให้ ถ้าไม่ตรงจะไม่นำเข้า
   - สร้างผู้ดูแลของผู้ให้บริการ เช่น `cli create-admin ops "ผู้ให้บริการ" <รหัส>`
2. **ส่งออก (เครื่องเดิม):** ลูกค้าผู้ใช้บริการ → คลิกลูกค้า → **⬇ ส่งออกเพื่อย้าย…** → ตั้งรหัสผ่านของแฟ้ม
   - แนะนำทำนอกเวลาทำงาน หรือระงับลูกค้าชั่วคราวก่อน ถ้ามีการบันทึกหลังส่งออก ข้อมูลส่วนนั้นจะไม่ไปด้วย
3. **นำเข้า (เครื่องใหม่):** เข้าระบบด้วยผู้ดูแลของผู้ให้บริการ
   - เครื่องใหม่ที่ยังไม่มีบริษัท: หน้าแรกมีปุ่ม "ลูกค้าผู้ใช้บริการ / รับลูกค้าที่ย้ายมา"
   - กด **⬆ รับลูกค้าที่ย้ายมา…** → เลือกแฟ้ม แล้วใส่รหัสผ่าน
   - ระบบนำเข้าในทรานแซกชันเดียว ถ้าไม่สำเร็จจะไม่มีข้อมูลใดถูกบันทึก
   - หลังนำเข้า ระบบแสดงจำนวนใบสำคัญและยอดเดบิต/เครดิตรวมรายบริษัท เทียบเดิมกับใหม่ ต้องขึ้น ✅ ตรง ทุกบริษัท
   - ถ้าเครื่องใหม่มีลูกค้า บริษัท หรือรหัสผู้ใช้ซ้ำกับในแฟ้ม ระบบจะไม่นำเข้าและบอกว่าซ้ำอะไร
4. **ตรวจ:** ให้ผู้ใช้ของลูกค้าเข้าเครื่องใหม่ด้วยรหัสเดิม แล้วเปิดงบทดลองเทียบกับเครื่องเดิม
5. **ปิดที่เครื่องเดิม:** คลิกลูกค้า → ใส่ **ย้ายไปที่** (ที่อยู่ของเครื่องใหม่) → เปลี่ยนสถานะเป็น **เลิกใช้** → บันทึก
   - ผู้ใช้ที่เข้าเครื่องเดิมจะเห็นข้อความ "บัญชีของท่านย้ายไปใช้ที่ … แล้ว"
6. **ลบสำเนาที่เครื่องเดิม:** กด **ลบข้อมูลทั้งหมดของลูกค้า…** ซึ่งเป็นการลบของ T0.17
   - ลูกค้าที่ย้ายแล้วไม่ต้องรอ 90 วัน
   - แฟ้มบันทึกเหตุการณ์เดิมคงไว้ตามกฎหมาย

**ลูกค้าขนาดใหญ่มาก (แฟ้มเกิน 1 GB):** ใช้คำสั่งแทนหน้าจอ รหัสผ่านของแฟ้มตั้งเป็นตัวแปร ไม่พิมพ์ในบรรทัดคำสั่ง

```powershell
$env:BUDDY_TENANT_PASSPHRASE = '<รหัสผ่านของแฟ้ม>'
pnpm --filter @buddy/server cli tenant-export <รหัสลูกค้า> D:\ย้าย\ลูกค้า.buddy-tenant   # เครื่องเดิม
pnpm --filter @buddy/server cli tenant-import D:\ย้าย\ลูกค้า.buddy-tenant                 # เครื่องใหม่ (ผลตรวจไม่ตรง = exit code 2)
```

## ผลทดสอบ (30/10/2569)

- **ข้อมูล DEMO:** ย้ายจาก PostgreSQL ไปฐาน PGlite ใหม่ที่แยกขาด
  - 365,695 แถว แฟ้ม 26.7 MB
  - ส่งออก 8 วินาที นำเข้า 36 วินาที
  - ใบสำคัญ 16,790 ใบ เดบิต = เครดิต 1,422,373,894.87 ตรงทั้งสองฝั่ง
  - ยอดเคลื่อนไหวปี 2569 ที่เครื่องใหม่ 825,162,812.82 (รวม RR0002237 ที่เจ้าของคีย์ทดสอบ)
- **ชุดทดสอบอัตโนมัติ** (ฐานข้อมูลสองชุดในโปรแกรมเดียว) ตรวจว่า:
  - รหัสผ่านและ 2FA เดิมใช้ได้ สิทธิ์รายเมนูตามเดิม งบทดลองเท่ากัน งวดที่ปิดยังปิด
  - นำเข้าซ้ำไม่ได้ ใส่รหัสผ่านแฟ้มผิดไม่ได้ เฉพาะผู้ให้บริการทำได้
  - ผู้ใช้เข้าเครื่องเดิมแล้วได้รับที่อยู่ใหม่ ลบสำเนาเดิมได้ทันที
- **ผ่านหน้าจอจริง:** ใช้เครื่องทดสอบสองเครื่อง (พอร์ต 4101 → 4102)
