# ข้อมูลส่วนบุคคล (PDPA) — Buddy Account

พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 · งาน T0.17

> เอกสารนี้อธิบายสิ่งที่โปรแกรมทำให้ และแบบร่างข้อตกลงที่ผู้ให้บริการใช้กับลูกค้า **แบบร่างข้อตกลงยังไม่ได้ผ่านการตรวจของนักกฎหมาย** ต้องให้นักกฎหมายตรวจก่อนใช้จริง

## 1. ใครมีหน้าที่อะไร

| ฝ่าย | ฐานะตามกฎหมาย | หน้าที่ |
|---|---|---|
| ลูกค้าผู้ใช้บริการ (บริษัทหรือสำนักงานบัญชีที่ใช้โปรแกรม) | **ผู้ควบคุมข้อมูล** ของข้อมูลลูกค้า ผู้จำหน่าย และพนักงานที่บันทึกในโปรแกรม | ตอบคำขอของเจ้าของข้อมูล บันทึกทะเบียนคำขอ ตัดสินใจลบ/ปิดบัง |
| ผู้ให้บริการ Buddy Account | **ผู้ประมวลผลข้อมูล** (เก็บรักษาข้อมูลแทนลูกค้า) และผู้ควบคุมข้อมูลของบัญชีผู้ใช้/ข้อมูลติดต่อของลูกค้าผู้ใช้บริการ | รักษาความปลอดภัย ไม่ใช้ข้อมูลนอกเหนือคำสั่ง ลบหรือคืนข้อมูลเมื่อเลิกใช้บริการ |
| Anthropic (เฉพาะลูกค้าที่เปิด AI อ่านบิล) | ผู้ประมวลผลช่วง (ส่งไปสหรัฐอเมริกา) | อ่านภาพบิลที่ผู้ใช้เลือกส่ง ใช้กุญแจ API ของลูกค้าเอง |

## 2. หน้าจอ เริ่มระบบ › ข้อมูลส่วนบุคคล (PDPA) — `/settings/pdpa`

ใช้ได้เฉพาะผู้ใช้ระดับอนุมัติ 9 หรือผู้ดูแลระบบ (เมนู `SET.PDPA` อยู่ในชุดความปลอดภัย และกุญแจ API ใช้ไม่ได้)

- **เจ้าของข้อมูล:** ค้นหาจากรหัส ชื่อ เลขผู้เสียภาษี โทรศัพท์ หรืออีเมล ในลูกค้า ผู้จำหน่าย พนักงานขาย และผู้ติดต่อ แล้วคลิกเพื่อดูข้อมูลทั้งหมดที่เก็บไว้ ได้แก่ แฟ้มหลัก ผู้ติดต่อ สถานที่ส่งของ บัญชีธนาคาร หมายเหตุ เอกสารที่อ้างถึง และแฟ้มภาษี
  - **ส่งออกสำเนา (JSON):** ใช้กับคำขอดูข้อมูลหรือขอรับสำเนา (ม.30) และคำขอโอนย้ายข้อมูล (ม.31) ระบบบันทึกคำขอให้อัตโนมัติ
  - **ลบข้อมูลติดต่อ:** ลบได้ทุกเมื่อ ได้แก่ โทรศัพท์ อีเมล ผู้ติดต่อ หมายเหตุ บัญชีธนาคารของผู้จำหน่าย และที่อยู่ เลขผู้เสียภาษี เลขประกันสังคมของพนักงานขาย
    - ชื่อ ที่อยู่ และเลขผู้เสียภาษีของลูกค้า/ผู้จำหน่ายยังคงไว้ เพราะต้องใช้ในเอกสารภาษี
  - **ปิดบังทั้งหมด:** ทำได้เมื่อเอกสารล่าสุดพ้นระยะเก็บรักษาแล้ว
    - ระยะเก็บคือ 5 ปีนับจากวันสิ้นปีบัญชีของเอกสารนั้น ตาม พ.ร.บ.การบัญชี 2543 ม.14 และประมวลรัษฎากร ม.87/3
    - ระบบเปลี่ยนชื่อเป็น "ลบตาม PDPA" และลบที่อยู่และเลขผู้เสียภาษี ทั้งในแฟ้มหลัก เอกสาร แฟ้มภาษีซื้อ/ขาย ภาษีหัก ณ ที่จ่าย เช็ค และบัตรรับประกัน
    - ยอดเงินไม่เปลี่ยน งบทดลองจึงเท่าเดิม
  - ทุกการลบต้องพิมพ์รหัสของเจ้าของข้อมูลเพื่อยืนยัน การลบเรียกคืนไม่ได้
- **ทะเบียนคำขอ:** บันทึกคำขอทุกชนิด ตาม ม.39 ซึ่งกำหนดให้บันทึกคำขอที่ปฏิเสธพร้อมเหตุผลด้วย
  - ชนิดคำขอ: ขอดู/ขอรับสำเนา · ขอโอนย้าย · ขอแก้ไข · ขอลบ · คัดค้าน/ระงับใช้
  - ผลของคำขอ: รอดำเนินการ · ดำเนินการแล้ว · ปฏิเสธ (ต้องมีเหตุผล)
  - กฎหมายให้ตอบเจ้าของข้อมูลภายใน 30 วัน
  - ทะเบียนเก็บเฉพาะรหัสของเจ้าของข้อมูล ไม่เก็บชื่อ
- **ทะเบียนข้อมูลส่วนบุคคล:** รายการข้อมูลบุคคลที่โปรแกรมเก็บ แต่ละรายการบอกตาราง/ช่องข้อมูล เจ้าของข้อมูล วัตถุประสงค์ ฐานทางกฎหมาย ระยะเก็บ วิธีลบ การส่งต่อภายนอก และจำนวนแถวที่มีในบริษัทนี้
  - ส่งออกเป็น Excel (CSV) ได้
  - รายการทั้งหมดอยู่ที่ `packages/core/src/pdpa.ts` (`PDPA_REGISTER`)
  - **เพิ่มช่องที่เก็บข้อมูลบุคคลในฐานข้อมูลต้องเพิ่มในทะเบียนด้วย** ชุดทดสอบตรวจทุกช่องที่ชื่อเหมือนข้อมูลบุคคล (`PDPA_COLUMN_PATTERN`) ถ้าช่องนั้นไม่ใช่ข้อมูลบุคคลให้ใส่ใน `PDPA_NOT_PERSONAL` พร้อมเหตุผล

## 3. เลิกใช้บริการ — หน้า ลูกค้าผู้ใช้บริการ (เฉพาะผู้ให้บริการ)

1. บันทึกวันที่ลงนามข้อตกลงประมวลผลข้อมูล (DPA) ในช่อง "ลงนามข้อตกลงประมวลผลข้อมูล" รายการที่ยังไม่ลงนามจะแสดงว่า "ยังไม่ลงนาม"
2. เมื่อลูกค้าเลิกใช้บริการ ให้เปลี่ยนสถานะเป็น **เลิกใช้**
   - ผู้ใช้ทุกคนของลูกค้ารายนั้นเข้าระบบไม่ได้ทันที
   - ระบบบันทึกวันเลิกใช้ และวันที่ลบได้ ซึ่งเท่ากับวันเลิกใช้ + 90 วัน
3. ภายใน 90 วัน ถ้าลูกค้าขอข้อมูล ผู้ให้บริการเลือกบริษัทของลูกค้าแล้วสำรองข้อมูล (อื่น ๆ › สำรองข้อมูล) ส่งแฟ้ม .buddy ให้ลูกค้า
   - ถ้าลูกค้ากลับมาใช้ ให้เปลี่ยนสถานะเป็นใช้งาน ระบบจะยกเลิกกำหนดลบเอง
4. ครบ 90 วันแล้ว กด **ลบข้อมูลทั้งหมดของลูกค้า…** แล้วพิมพ์รหัสลูกค้าเพื่อยืนยัน ทุกขั้นทำในทรานแซกชันเดียว (ถ้าไม่สำเร็จจะไม่มีอะไรถูกลบ)
   - **ลบ:** ทุกตารางของทุกบริษัทของลูกค้า (เอกสาร ใบสำคัญ แฟ้มหลัก ภาษี ค่าตั้งค่า กุญแจ API กุญแจ AI) รวมทั้งการเข้าระบบ 2FA และการผูกบริษัทของผู้ใช้
   - **คงไว้แต่ปิดบังแล้ว:** แถวบริษัท ผู้ใช้ และลูกค้าผู้ใช้บริการ (เหลือเฉพาะรหัส) และเครื่อง/สาขาที่แฟ้มบันทึกเหตุการณ์อ้างถึง
   - **คงไว้ตามเดิม:** แฟ้มบันทึกเหตุการณ์ (เพิ่มได้อย่างเดียว ตามกติกาโครงการ)
   - หลังลบแล้ว ลูกค้ารายนี้แก้ไขหรือเปิดใช้อีกไม่ได้ และรหัสบริษัทเดิมนำไปสร้างบริษัทใหม่ได้

## 4. ข้อจำกัดที่ต้องรู้

- **แฟ้มบันทึกเหตุการณ์** (`sys_activity_log`) เก็บค่าก่อน/หลังแก้ไข ซึ่งอาจมีข้อมูลบุคคลเดิมอยู่ และโปรแกรมลบไม่ได้ เพราะกติกาโครงการห้ามแก้/ลบ log
  - ฐานทางกฎหมายที่ใช้เก็บคือ หน้าที่ตามกฎหมายบัญชีและการตรวจสอบย้อนหลัง
  - ถ้าต้องการลบ log ที่เก่ากว่าระยะเก็บ ต้องตัดสินใจเป็นนโยบายก่อน
- **แฟ้มสำรองเก่า** (.buddy) ยังมีข้อมูลเดิม ถ้านำแฟ้มสำรองกลับมาใช้หลังจากลบไปแล้ว ต้องลบซ้ำ
  - ผู้ให้บริการควรกำหนดอายุแฟ้มสำรองของตัวเอง
- **ข้อมูลที่ผู้ใช้แก้เองก่อนหน้า** เช่น ผู้ติดต่อหรือสถานที่ส่งที่ถูกลบจากหน้าจอ ยังมีแถวเก่าแบบ soft delete การลบตาม PDPA จะล้างแถวเก่าเหล่านี้ด้วย ยกเว้นค่าก่อนแก้ไขที่อยู่ในแฟ้มบันทึกเหตุการณ์
- **การปิดบังทั้งหมด** ลบข้อมูลเฉพาะในเอกสารที่ผูกกับรหัสลูกค้า/ผู้จำหน่ายนั้น
  - รายการภาษีที่บันทึกเองโดยไม่ผูกเอกสาร และพิมพ์ชื่อเองโดยไม่เลือกรหัส จะไม่ถูกล้าง
  - รายการเหล่านี้ต้องค้นและแก้ที่หน้าแฟ้มภาษี
- ระบบจับเวลา 30 วันให้ผู้ใช้ได้ แต่ไม่ส่งการแจ้งเตือน ผู้ใช้ต้องดูทะเบียนคำขอเอง แถบทะเบียนคำขอแสดงจำนวนคำขอที่รอดำเนินการ

## 5. แบบร่างข้อตกลงการประมวลผลข้อมูลส่วนบุคคล (Data Processing Agreement)

> แบบร่างเพื่อเริ่มต้น — ให้นักกฎหมายตรวจ/ปรับก่อนใช้

**ข้อตกลงการประมวลผลข้อมูลส่วนบุคคล** ระหว่าง ____________ ("ลูกค้า" ผู้ควบคุมข้อมูล) กับ ____________ ("ผู้ให้บริการ" ผู้ประมวลผลข้อมูล) ทำขึ้นเมื่อวันที่ ________

1. **ขอบเขต:** ผู้ให้บริการประมวลผลข้อมูลส่วนบุคคลที่ลูกค้าบันทึกในโปรแกรม Buddy Account เฉพาะเพื่อให้บริการโปรแกรมบัญชีตามสัญญาให้บริการ ได้แก่ เก็บรักษา สำรอง กู้คืน และให้ลูกค้าเรียกใช้ ข้อมูลมีดังนี้
   - ประเภทข้อมูล: ตามทะเบียนข้อมูลส่วนบุคคลในโปรแกรม
   - เจ้าของข้อมูล: ลูกค้า ผู้จำหน่าย ผู้ติดต่อ และพนักงานของลูกค้า
2. **คำสั่งของลูกค้า:** ผู้ให้บริการประมวลผลตามคำสั่งเป็นลายลักษณ์อักษรของลูกค้าเท่านั้น การใช้งานผ่านโปรแกรมถือเป็นคำสั่ง ผู้ให้บริการไม่นำข้อมูลไปใช้เพื่อวัตถุประสงค์อื่น ไม่ขาย และไม่เปิดเผยแก่บุคคลอื่น เว้นแต่กฎหมายบังคับ
3. **ความปลอดภัย:** มาตรการขั้นต่ำมีดังนี้
   - แยกข้อมูลลูกค้าแต่ละรายด้วยการกรองในโปรแกรมและ Row-Level Security ในฐานข้อมูล
   - รหัสผ่านเก็บแบบ bcrypt
   - ยืนยันตัวตนสองขั้นบังคับผู้ดูแลระบบ และล็อกบัญชีเมื่อใส่รหัสผิด
   - ค่าลับเข้ารหัส AES-256-GCM
   - แฟ้มบันทึกเหตุการณ์แก้ไขไม่ได้
   - จำกัดสิทธิ์รายเมนู
4. **บุคลากร:** ผู้ที่เข้าถึงข้อมูลได้มีหน้าที่รักษาความลับ และเข้าถึงเท่าที่จำเป็นต่อการให้บริการหรือแก้ปัญหาตามที่ลูกค้าขอ
5. **ผู้ประมวลผลช่วง:** ผู้ให้บริการต้องแจ้งลูกค้าล่วงหน้าก่อนใช้ผู้ประมวลผลช่วงรายใหม่ รายที่ใช้อยู่แล้วมีดังนี้
   - ผู้ให้บริการเครื่องแม่ข่าย: ____________
   - Anthropic, PBC (สหรัฐอเมริกา) เฉพาะเมื่อลูกค้าเปิด "AI อ่านบิล" ด้วยกุญแจ API ของลูกค้าเอง ลูกค้าเป็นผู้ตัดสินใจส่งข้อมูลไปต่างประเทศ (ม.28–29)
6. **ช่วยตอบคำขอของเจ้าของข้อมูล:** ผู้ให้บริการจัดเครื่องมือในโปรแกรมให้ลูกค้าตอบคำขอเอง ได้แก่ ค้นหา ส่งออกสำเนา ลบ/ปิดบัง และทะเบียนคำขอ และช่วยเพิ่มเติมเมื่อลูกค้าร้องขอ
7. **เหตุละเมิดข้อมูล:** ผู้ให้บริการแจ้งลูกค้าโดยไม่ชักช้า ภายใน 24 ชั่วโมงนับแต่ทราบ เพื่อให้ลูกค้าแจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคลได้ภายใน 72 ชั่วโมง (ม.37(4))
8. **สิ้นสุดการให้บริการ:** เมื่อเลิกใช้บริการ ผู้ให้บริการทำดังนี้
   - ปิดการเข้าระบบทันที
   - ภายใน 90 วัน ส่งแฟ้มสำรองข้อมูลให้ลูกค้าเมื่อลูกค้าขอ
   - เมื่อครบ 90 วัน ลบข้อมูลทั้งหมดของลูกค้าออกจากระบบ ยกเว้นแฟ้มบันทึกเหตุการณ์ซึ่งเก็บตามกฎหมาย/การตรวจสอบ และแฟ้มสำรองของผู้ให้บริการซึ่งหมดอายุตามรอบ ____ วัน
   - ลูกค้ามีหน้าที่เก็บเอกสารบัญชีตามกฎหมายเอง
9. **การตรวจสอบ:** ลูกค้าขอข้อมูลที่จำเป็นเพื่อแสดงว่าผู้ให้บริการปฏิบัติตามข้อตกลงนี้ได้ ปีละไม่เกิน ____ ครั้ง
