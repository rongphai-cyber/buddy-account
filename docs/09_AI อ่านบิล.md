## ตั้งค่า (เริ่มระบบ › AI อ่านบิล (Claude) — `/settings/ai`, เมนู `SET.AI` ระดับ 9)

- **กุญแจ API ของ Anthropic** (sk-ant-…) ต่อบริษัท — ผู้ดูแลใส่เอง ค่าใช้จ่ายเรียกเก็บกับบัญชี Anthropic ของกิจการ
  เก็บในตาราง `sys_secret` เข้ารหัส AES-256-GCM (`apps/server/src/secret.ts`) ด้วยกุญแจหลัก `BUDDY_SECRET_KEY` หรือแฟ้ม `BUDDY_SECRET_FILE` (ค่าเริ่มต้น `.data/secret.key`; ตัวติดตั้ง Windows = โฟลเดอร์ข้อมูล) · หน้าจอเห็นเฉพาะ 4 ตัวท้าย · ไม่อยู่ในแฟ้มสำรอง/คัดลอกบริษัท
- **เพดานค่าใช้จ่ายต่อเดือน** (ดอลลาร์สหรัฐ, ค่าเริ่มต้น 20, ว่าง = ไม่จำกัด) — ตรวจก่อนเรียกทุกครั้ง ครบแล้วปุ่มใช้ไม่ได้จนถึงเดือนถัดไป
- ตารางการใช้งานเดือนนี้ (`sys_ai_usage`): ผู้ใช้ แฟ้ม ผล โทเคนเข้า/ออก ค่าใช้จ่าย — รวมครั้งที่ผิดพลาด/ถูกปฏิเสธ (มีค่าใช้จ่ายก็นับ)

## ใช้งาน

ปุ่ม **📷 อ่านบิลด้วย AI** (แสดงเมื่อบริษัทมีกุญแจ) ใน ซื้อเงินเชื่อ/ซื้อเงินสด และบันทึกค่าใช้จ่ายอื่น ๆ → เลือกรูป JPG/PNG/WEBP/GIF หรือ PDF (≤ 10 MB) → อ่านบิล (10–60 วินาที) → ตรวจผล → ใส่ลงเอกสาร

- ผู้จำหน่าย: จับคู่ตามเลขผู้เสียภาษี (+สาขา) · ไม่พบ = ซื้อ: เลือก/เพิ่มเอง · ค่าใช้จ่ายอื่น: ใส่เป็นชื่อ
- เลขที่/วันที่บิล → ช่องเลขที่ใบกำกับผู้จำหน่าย (เข้าแฟ้มภาษีซื้อ) · ประเภทราคา/อัตรา VAT ตามบิล
- รายการ: จับคู่สินค้า (ซื้อ) / รหัสค่าใช้จ่าย (ค่าใช้จ่ายอื่น) ตามชื่อที่ตรงกัน · ไม่พบ = คงคำอธิบายและราคาไว้ให้เลือกรหัส (เลือกแล้วราคาตามบิลไม่ถูกแทนด้วยราคาทุนมาตรฐาน) · ส่วนต่าง จำนวน×ราคา กับยอดบรรทัด = ส่วนลดบรรทัด
- ข้อสังเกตให้ตรวจ (`normalizeBill` ใน `packages/core/src/ai-bill.ts`): ยอดรวมไม่สอดคล้อง VAT ไม่ตรงอัตรา ปี พ.ศ. ใบกำกับอย่างย่อ เลขผู้เสียภาษีไม่ครบ อ่านราคาไม่ได้ และหมายเหตุจาก AI
- **ภาษีหัก ณ ที่จ่ายในบิล** (HANDOFF 167 · บิลจริง RE260219025: ก่อน VAT 58,244.93 + VAT 4,077.15 − หัก 3% 1,747.35 = 60,574.73): ช่อง `wht_amount` ใน BILL_SCHEMA (ข้อความ ไม่มี = "" — ไม่มีช่อง union ตามกฎ HANDOFF 166) · ตรวจยอดรวม: รายการ − ส่วนลด (+ VAT เมื่อราคาแยกภาษี) ตรงกับยอดรวมที่พิมพ์ **หรือ** ตรงหลังหักภาษี ณ ที่จ่าย = ไม่เตือน · ฐาน = ยอดก่อน VAT (subtotal) · อัตรา = ภาษี ÷ ฐาน ปัดเป็นอัตรามาตรฐาน 1 2 3 5% เมื่อห่างไม่เกิน 0.05 จุด (`whtRateOf`) ไม่ใกล้อัตราใด = เว้นอัตราให้ผู้ใช้ใส่ + เตือน · ร่างเอกสาร: ค่าใช้จ่ายอื่น (OE) และซื้อเงินสด (HP) เติมแท็บภาษีหัก ณ ที่จ่าย 1 แถว (`billWhtRow`: แบบ ภ.ง.ด. ตามเลขผู้เสียภาษีผู้ขาย · ประเภทเงินได้ตามอัตรา 3% ค่าบริการ 1% ค่าขนส่ง 2% ค่าโฆษณา 5% ค่าเช่า) · ซื้อเงินเชื่อ (RR) ไม่มีแท็บนี้ — แจ้งให้บันทึกตอนจ่ายชำระหนี้ · บริษัทไม่จด VAT/เจ้าหนี้กลางไม่เติม

## ตรวจผู้จำหน่ายและบิลซ้ำ (เพิ่มตามคำขอเจ้าของ 29/10/2569)

`checkSupplier` ใน `modules/ai.ts` เทียบกับแฟ้มผู้จำหน่ายของบริษัทนี้:

| ผล | ความหมาย |
|---|---|
| match | เลขผู้เสียภาษี (+สาขา) ตรงกับผู้จำหน่ายในแฟ้ม ชื่อใกล้เคียง → เลือกผู้จำหน่ายให้ |
| name_mismatch | เลขตรงแต่ชื่อในบิลต่างจากแฟ้มมาก → เลือกให้แต่เตือนให้ตรวจ |
| branch_mismatch | เลขตรงแต่สาขาในบิลไม่ตรงกับแฟ้ม → เตือน (ภาษีซื้อใช้สาขาตามใบกำกับ) |
| tax_mismatch | ไม่พบตามเลข แต่มีชื่อคล้าย (เลขในแฟ้มต่างกัน) → ไม่เลือกให้ ให้ติ๊ก "ใช้ …" เองถ้าแน่ใจ |
| no_tax | ชื่อคล้ายผู้จำหน่ายที่แฟ้มยังไม่มีเลขผู้เสียภาษี → แนะนำให้เพิ่มเลข |
| new | ผู้จำหน่ายใหม่ → เพิ่มที่แฟ้มก่อนบันทึก |

ทุกกรณีตรวจเลขตรวจสอบหลักที่ 13 ด้วย (`checkTaxId`) · **บิลซ้ำ**: ผู้จำหน่ายเดียวกัน + เลขที่บิล (ref_no) ที่ยังไม่ยกเลิก → แจ้งเลขที่เอกสารเดิม

## แนะนำการลงบัญชีรายบรรทัด (ให้พนักงานบัญชีตรวจและยืนยัน)

`suggestLines` ใช้ **ข้อมูลของบริษัทนี้เท่านั้น**:
1. **ประวัติ** — บรรทัดซื้อ/ค่าใช้จ่ายที่บันทึกแล้ว 3 ปีล่าสุด (RR HP OE ที่ไม่ยกเลิก) คำอธิบายคล้ายกัน (`textSim` เทียบตัวอักษรคู่ ใช้กับภาษาไทยที่ไม่เว้นวรรคได้) · ผู้จำหน่ายเดียวกันได้น้ำหนักมากกว่า — เอกสารที่ยืนยันแล้วจึงเป็น "การเรียนรู้" โดยไม่ต้องมีตารางแยก
2. **แฟ้มรหัส** — ชื่อและหมายเหตุของรหัสสินค้า/รหัสค่าใช้จ่ายที่ใช้กับเอกสารนั้นได้ (ซื้อ: ชนิด 0 1 2 3 5 · ค่าใช้จ่ายอื่น: 5 2) พร้อมบัญชีที่จะลง
3. **Claude** (ครั้งที่ 2 ข้อความล้วน effort low) เลือกจากรายการข้อ 1–2 ตาม **ประเภทธุรกิจ** และ **แนวทางการลงบัญชีของบริษัท** (`ai.business_type`, `ai.guidance` ตั้งที่ เริ่มระบบ › AI อ่านบิล) · รหัสที่ไม่มีในแฟ้มถูกตัดทิ้ง · เรียกไม่สำเร็จใช้ประวัติ/ชื่อแทน · ค่าใช้จ่ายนับรวมในเพดาน (`sys_ai_usage.purpose = SUGGEST`)

หน้าต่างอ่านบิลแสดงรหัสแนะนำ (★) บัญชีที่จะลง ความมั่นใจ (มั่นใจ/น่าจะใช่/ไม่แน่ใจ) ที่มา (ประวัติ/AI/ชื่อรหัส) และเหตุผล · เลือกรหัสอื่นหรือ "ไม่ใส่รหัส" ได้ทุกบรรทัด · ค่าเริ่มต้นใส่เฉพาะที่ไม่ใช่ "ไม่แน่ใจ"

### ใส่ข้อมูลอย่างไรให้แนะนำได้แม่น (แสดงในหน้าตั้งค่าด้วย)
1. ตั้งชื่อรหัสสินค้า/ค่าใช้จ่ายให้ตรงกับที่พิมพ์ในบิล และใส่คำที่มักเจอในช่องหมายเหตุของรหัส (เช่น ค่าน้ำมัน: "ดีเซล แก๊สโซฮอล์ ปตท บางจาก")
2. ผูกบัญชีของกลุ่มบัญชีสินค้าและรหัสค่าใช้จ่ายให้ครบ
3. แฟ้มผู้จำหน่ายมีเลขผู้เสียภาษีและสาขา
4. เขียนแนวทางของบริษัท (เกณฑ์สินทรัพย์ ผู้จำหน่ายประจำ รายการพิเศษ)
5. ยืนยันทุกครั้งก่อนบันทึก — ครั้งต่อไปรายการเดิมจะแนะนำรหัสเดิมได้มั่นใจขึ้น

## การเรียก Claude (`apps/server/src/modules/ai.ts`)

- `client.beta.messages.parse` · รุ่นตามค่าตั้งของบริษัท `ai.model` (หน้า AI อ่านบิล › รุ่น AI · HANDOFF 166): `claude-haiku-5-5` ประหยัดที่สุด (**ค่าเริ่มต้นทุกบริษัท**) · `claude-sonnet-5-5` สมดุล · `claude-opus-5-5` แม่นยำที่สุด — ใช้ทั้งอ่านบิลและแนะนำรหัส
- `output_config: { effort: 'medium' (อ่านบิล) / 'low' (แนะนำรหัส), format: jsonSchemaOutputFormat(BILL_SCHEMA) }` (structured outputs) · ไม่ส่ง thinking
- โครงข้อมูล (BILL_SCHEMA / SUGGEST_SCHEMA) **ไม่มีช่อง null/anyOf เลย** — ไม่มี/อ่านไม่ออก = `""` · Anthropic จำกัดช่องแบบ union ไม่เกิน 16 ช่องต่อโครง (เดิม 18 ช่อง → 400 "too many parameters with union types" — HANDOFF 166) · ชุดทดสอบใน core นับช่องให้ทุกครั้ง · normalizeBill ถือ `""` / null / "null" / "-" เป็น "ไม่มี" เหมือนกัน
- Sonnet/Opus ที่ปฏิเสธส่งต่อรุ่นสำรองอัตโนมัติ: `betas: ['server-side-fallback-2026-07-01']`, `fallbacks: 'default'` · **Haiku ไม่ส่งทั้งสองค่า** (ไม่มีรุ่นสำรอง — ส่งแล้วได้ 400) ปฏิเสธ = แจ้ง "AI ปฏิเสธการอ่านแฟ้มนี้ — ป้อนเอง"
- รูป = `image` base64 · PDF = `document` base64 · ข้อความระบบภาษาไทยกำหนดกติกา (ผู้ขาย ปี ค.ศ. ทศนิยมเป็นข้อความ ห้ามเดา)
- ค่าใช้จ่าย (`aiCost`): ราคาต่อ 1 ล้านโทเคนของ Anthropic (พ.ย. 2569) Haiku 5.5 = $0.10 เข้า / $0.50 ออก (คำขอเกิน 100,000 โทเคน $0.50 / $2.50 ทั้งคำขอ) · Sonnet 5.5 = $2 / $10 · Opus 5.5 = $4 / $20 · อ่านแคช 0.1 เท่าของขาเข้า (โปรแกรมไม่ได้ใช้แคช) · ถ้ารุ่นสำรองตอบ คิดตามรุ่นที่แพงกว่า · รุ่นที่ไม่รู้จักคิดสูงสุด · หน้าตั้งค่าแสดงค่าประมาณต่อบิล (`aiBillEstimate`: อ่านบิล 4,000/1,500 โทเคน + แนะนำรหัส 2,000/400) Haiku ≈ $0.0016 · Sonnet ≈ $0.031 · Opus ≈ $0.062
- ผิดพลาด: กุญแจผิด/ไม่มีสิทธิ์/เครดิตหมด/เรียกถี่/ขัดข้อง → ข้อความไทยบอกวิธีแก้ · บันทึกการใช้ก่อนตอบ (ไม่ throw เพื่อไม่ให้ทรานแซกชันของคำขอย้อนรายการ)
- ชุดทดสอบใช้ client จำลอง (`setAiClientFactory`) ไม่เรียก API จริง

## ให้ AI จัดรูปแบบ Excel ที่นำเข้า (HANDOFF 168 · เจ้าของ "ทำทาง ก" 20/11/2569)
- ที่ไหน: นำเข้ารายการขาย/ซื้อ/ค่าใช้จ่ายอื่น (`/tools/trade-import` ทุกชนิด รวม OE) และนำเข้าใบสำคัญ (`/gl/journals/import`) · รับชำระ/จ่ายชำระ (RE/PS) ยังไม่มีหน้านำเข้า — ไม่อยู่ในงานนี้
- ลำดับ: เลือกแฟ้ม → `POST /api/v1/import-map/analyze` (ตรงแบบฟอร์ม = ตรวจเลย · มีการจับคู่ที่บันทึกไว้ของหัวตารางนี้ = ใช้เลย "ใช้การจับคู่ที่บันทึกไว้ (ไม่เสียค่า AI)" · ไม่ตรง = หน้าจับคู่ เดาให้ก่อนด้วย `guessMapping` ไม่ใช้ AI) → ปุ่ม "✨ ให้ AI จัดรูปแบบ" (`/import-map/ai`) → ผู้ใช้ตรวจ/แก้รายคอลัมน์ (ตัวอย่างข้อมูล 3 ค่า · คอลัมน์บังคับที่ยังไม่จับคู่เป็นสีแดง) → "ใช้การจับคู่นี้" (`/import-map/save` แล้วตรวจแฟ้ม) → ขั้นตรวจ/นำเข้าเดิม
- AI เห็นเฉพาะต้นแฟ้มไม่เกิน 25 แถว ช่องละไม่เกิน 60 ตัว + คอลัมน์ของแบบฟอร์ม (`mapPrompt`) — ไม่ส่งทั้งแฟ้ม · ตอบ "การจับคู่" (`mapSchema` ไม่มีช่อง union): แถวหัวตาราง · คอลัมน์ปลายทาง → คอลัมน์ต้นทางหรือค่าคงที่ · ลำดับวันที่ dmy/mdy/ymd · ปี พ.ศ./ค.ศ./ดูจากตัวเลข · ทศนิยมจุด/จุลภาค · รวมแถว (เลขที่เดียวกัน/แถวเลขที่ว่างต่อเอกสารด้านบน/แถวละเอกสาร) · คำที่บอกแถวไม่ใช่รายการ (รวม ยอดยกไป) · หมายเหตุให้ผู้ใช้ตรวจ
- แปลงทุกแถวแบบตายตัว `applyMapping` (packages/core/src/import-mapping.ts ไม่ใช้ AI): วันที่ไทย (15 ต.ค. 2569 · 15/10/69 · เลขไทย · เวลาท้าย) · ตัวเลข 1,234.50 / 1.234,50 / (500.00) / 500- / ฿ บาท · แถวต่อเนื่องรับหัวเอกสารจากแถวบน · ข้ามแถวรวม/แถวว่าง/หัวตารางซ้ำ (OCR หลายหน้า) · เลขแถวในข้อผิดพลาดตรงกับแฟ้มต้นฉบับ (ไม่มีหัวตาราง = +1 แจ้งบนหน้าจอ)
- จำการจับคู่: `sys_setting` คีย์ `imp.map.<หมวดเอกสาร>.<ลายมือหัวตาราง FNV-1a>` ของบริษัทใน session (ไม่มีตาราง/คอลัมน์ใหม่) · หาลายมือจาก 20 แถวแรก (หัวรายงานยาวไม่เท่ากันก็เจอ) · แฟ้มไม่มีหัวตารางจำไม่ได้
- แนะนำรหัส: แถวที่มีคำอธิบายแต่ไม่มีรหัสสินค้า/รหัสค่าใช้จ่าย/เลขที่บัญชี (`missingCodeRows`) → `/import-map/suggest` ประวัติของบริษัท (บรรทัดเอกสาร/ใบสำคัญ 3 ปี) + ชื่อรหัส (`textSim`) ก่อน · AI เฉพาะแถวที่เหลือ ครั้งเดียว เมื่อผู้ใช้กด "ให้ AI แนะนำที่เหลือ" (เลือกได้เฉพาะรหัสในรายการ) · ผู้ใช้ติ๊ก/เลือกแล้วกด "ใช้…ที่เลือก" → ส่ง `codes` (แถว → รหัส) ไปกับการตรวจ/นำเข้า (`setImportCodes` ไม่ทับรหัสที่มีในแฟ้ม) — ไม่เติมเงียบ
- ค่าใช้จ่าย: กุญแจ รุ่น (ค่าเริ่มต้น Haiku) เพดานรายเดือนเดียวกับ AI อ่านบิล · `sys_ai_usage` purpose MAP / SUGGEST · หน้าจอบอกค่าประมาณก่อนกดและค่าจริงหลังเรียก · AI ปิด/ไม่มีกุญแจ/ครบเพดาน = ซ่อนปุ่ม บอกให้เปิดที่ เริ่มระบบ › AI อ่านบิล (จับคู่เองได้)
- สิทธิ์: ใบสำคัญ = เพิ่มใบสำคัญ · ขาย/ซื้อ/ค่าใช้จ่าย = นำเข้ารายการขาย/ซื้อ + เพิ่มเอกสารชนิดนั้น · บันทึกประวัติ AI_IMPORT_MAP / IMPORT_MAP_SAVE · บรรทัด IMPORT บอก mapped/codes
