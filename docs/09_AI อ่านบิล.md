# AI อ่านบิล (T7.7)

ให้ Claude (Anthropic) อ่านรูป/PDF ของบิลผู้จำหน่าย แล้วเติมเป็น **ร่าง** ในเอกสารซื้อ — ผู้ใช้ตรวจ เลือกรหัสที่ยังไม่พบ แล้วบันทึกเอง (บันทึก = ลงบัญชีตามปกติ)
เจ้าของเลือก Claude (29/10/2569) · ใช้ชุดเชื่อมต่อทางการ `@anthropic-ai/sdk` 0.133.0 (เจ้าของอนุญาตให้ดาวน์โหลด)

## ตั้งค่า (เริ่มระบบ › AI อ่านบิล (Claude) — `/settings/ai`, เมนู `SET.AI` ระดับ 9)

- **กุญแจ API ของ Anthropic** (sk-ant-…) ต่อบริษัท — ผู้ดูแลใส่เอง ค่าใช้จ่ายเรียกเก็บกับบัญชี Anthropic ของกิจการ
  เก็บในตาราง `sys_secret` เข้ารหัส AES-256-GCM (`apps/server/src/secret.ts`) ด้วยกุญแจหลัก `BUDDY_SECRET_KEY` หรือแฟ้ม `BUDDY_SECRET_FILE` (ค่าเริ่มต้น `.data/secret.key`; ตัวติดตั้ง Windows = โฟลเดอร์ข้อมูล) · หน้าจอเห็นเฉพาะ 4 ตัวท้าย · ไม่อยู่ในแฟ้มสำรอง/คัดลอกบริษัท
- **เพดานค่าใช้จ่ายต่อเดือน** (ดอลลาร์สหรัฐ, ค่าเริ่มต้น 20, ว่าง = ไม่จำกัด) — ตรวจก่อนเรียกทุกครั้ง ครบแล้วปุ่มใช้ไม่ได้จนถึงเดือนถัดไป
- ตารางการใช้งานเดือนนี้ (`sys_ai_usage`): ผู้ใช้ แฟ้ม ผล โทเคนเข้า/ออก ค่าใช้จ่าย — รวมครั้งที่ผิดพลาด/ถูกปฏิเสธ (มีค่าใช้จ่ายก็นับ)

## ใช้งาน

ปุ่ม **📷 อ่านบิลด้วย AI** (แสดงเมื่อบริษัทมีกุญแจ) ใน ซื้อเงินเชื่อ/ซื้อเงินสด และบันทึกค่าใช้จ่ายอื่น ๆ → เลือกรูป JPG/PNG/WEBP/GIF หรือ PDF (≤ 10 MB) → อ่านบิล (10–60 วินาที) → ตรวจผล → ใส่ลงเอกสาร

- ผู้จำหน่าย: จับคู่ตามเลขผู้เสียภาษี (+สาขา) · ไม่พบ = ซื้อ: เลือก/เพิ่มเอง · ค่าใช้จ่ายอื่น: ใส่เป็นชื่อ
- เลขที่/วันที่บิล → ช่องเลขที่ใบกำกับผู้จำหน่าย (เข้าแฟ้มภาษีซื้อ) · ประเภทราคา/อัตรา VAT ตามบิล
- รายการ: จับคู่สินค้า (ซื้อ) / รหัสค่าใช้จ่าย (ค่าใช้จ่ายอื่น) ตามชื่อที่ตรงกัน · ไม่พบ = คงคำอธิบายและราคาไว้ให้เลือกรหัส (เลือกแล้วราคาตามบิลไม่ถูกแทนด้วยราคาทุนมาตรฐาน) · ส่วนต่าง จำนวน×ราคา กับยอดบรรทัด = ส่วนลดบรรทัด
- ข้อสังเกตให้ตรวจ (`normalizeBill` ใน `packages/core/src/ai-bill.ts`): ยอดรวมไม่สอดคล้อง VAT ไม่ตรงอัตรา ปี พ.ศ. ใบกำกับอย่างย่อ เลขผู้เสียภาษีไม่ครบ อ่านราคาไม่ได้ และหมายเหตุจาก AI

## ตรวจผู้จำหน่ายและบิลซ้ำ (เพิ่มตามคำขอเจ้าของ 29/10/2569)

`checkSupplier` ใน `modules/ai.ts` เทียบกับแฟ้มผู้จำหน่ายของบริษัทนี้:

| ผล | ความหมาย |
|---|---|
| match | เลขผู้เสียภาษี (+สาขา) ตรงกับผู้จำหน่ายในแฟ้ม ชื่อใกล้เคียง → เลือกผู้จำหน่ายให้ |
| name_mismatch | เลขตรงแต่ชื่อในบิลต่างจากแฟ้มมาก → เลือกให้แต่เตือนให้ตรวจ |
| branch_mismatch | เลขตรงแต่สาขาในบิลไม่ตรงกับแฟ้ม → เตือน (ภาษีซื้อใช้สาขาตามใบกำกับ) |
| tax_mismatch | ไม่พบตามเลข แต่มีชื่อคล้าย (เลขในแฟ้มต่างกัน) → ไม่เลือกให้ ให้ติ๊ก "ใช้ …" เองถ้าแน่ใจ |
| no_tax | ชื่อคล้ายผู้จำหน่ายที่แฟ้มยังไม่มีเลขผู้เสียภาษี → แนะนำให้เพิ่มเลข |
| new | ผู้จำหน่ายใหม่ → เพิ่มที่แฟ้มก่อนบันทึก |

ทุกกรณีตรวจเลขตรวจสอบหลักที่ 13 ด้วย (`checkTaxId`) · **บิลซ้ำ**: ผู้จำหน่ายเดียวกัน + เลขที่บิล (ref_no) ที่ยังไม่ยกเลิก → แจ้งเลขที่เอกสารเดิม

## แนะนำการลงบัญชีรายบรรทัด (ให้พนักงานบัญชีตรวจและยืนยัน)

`suggestLines` ใช้ **ข้อมูลของบริษัทนี้เท่านั้น**:
1. **ประวัติ** — บรรทัดซื้อ/ค่าใช้จ่ายที่บันทึกแล้ว 3 ปีล่าสุด (RR HP OE ที่ไม่ยกเลิก) คำอธิบายคล้ายกัน (`textSim` เทียบตัวอักษรคู่ ใช้กับภาษาไทยที่ไม่เว้นวรรคได้) · ผู้จำหน่ายเดียวกันได้น้ำหนักมากกว่า — เอกสารที่ยืนยันแล้วจึงเป็น "การเรียนรู้" โดยไม่ต้องมีตารางแยก
2. **แฟ้มรหัส** — ชื่อและหมายเหตุของรหัสสินค้า/รหัสค่าใช้จ่ายที่ใช้กับเอกสารนั้นได้ (ซื้อ: ชนิด 0 1 2 3 5 · ค่าใช้จ่ายอื่น: 5 2) พร้อมบัญชีที่จะลง
3. **Claude** (ครั้งที่ 2 ข้อความล้วน effort low) เลือกจากรายการข้อ 1–2 ตาม **ประเภทธุรกิจ** และ **แนวทางการลงบัญชีของบริษัท** (`ai.business_type`, `ai.guidance` ตั้งที่ เริ่มระบบ › AI อ่านบิล) · รหัสที่ไม่มีในแฟ้มถูกตัดทิ้ง · เรียกไม่สำเร็จใช้ประวัติ/ชื่อแทน · ค่าใช้จ่ายนับรวมในเพดาน (`sys_ai_usage.purpose = SUGGEST`)

หน้าต่างอ่านบิลแสดงรหัสแนะนำ (★) บัญชีที่จะลง ความมั่นใจ (มั่นใจ/น่าจะใช่/ไม่แน่ใจ) ที่มา (ประวัติ/AI/ชื่อรหัส) และเหตุผล · เลือกรหัสอื่นหรือ "ไม่ใส่รหัส" ได้ทุกบรรทัด · ค่าเริ่มต้นใส่เฉพาะที่ไม่ใช่ "ไม่แน่ใจ"

### ใส่ข้อมูลอย่างไรให้แนะนำได้แม่น (แสดงในหน้าตั้งค่าด้วย)
1. ตั้งชื่อรหัสสินค้า/ค่าใช้จ่ายให้ตรงกับที่พิมพ์ในบิล และใส่คำที่มักเจอในช่องหมายเหตุของรหัส (เช่น ค่าน้ำมัน: "ดีเซล แก๊สโซฮอล์ ปตท บางจาก")
2. ผูกบัญชีของกลุ่มบัญชีสินค้าและรหัสค่าใช้จ่ายให้ครบ
3. แฟ้มผู้จำหน่ายมีเลขผู้เสียภาษีและสาขา
4. เขียนแนวทางของบริษัท (เกณฑ์สินทรัพย์ ผู้จำหน่ายประจำ รายการพิเศษ)
5. ยืนยันทุกครั้งก่อนบันทึก — ครั้งต่อไปรายการเดิมจะแนะนำรหัสเดิมได้มั่นใจขึ้น

## การเรียก Claude (`apps/server/src/modules/ai.ts`)

- `client.beta.messages.parse` · รุ่น `claude-opus-5-5` · `output_config: { effort: 'medium', format: jsonSchemaOutputFormat(BILL_SCHEMA) }` (structured outputs)
- รุ่นที่ปฏิเสธส่งต่อรุ่นสำรองอัตโนมัติ: `betas: ['server-side-fallback-2026-07-01']`, `fallbacks: 'default'`
- รูป = `image` base64 · PDF = `document` base64 · ข้อความระบบภาษาไทยกำหนดกติกา (ผู้ขาย ปี ค.ศ. ทศนิยมเป็นข้อความ ห้ามเดา)
- ค่าใช้จ่าย (`aiCost`): ราคาต่อ 1 ล้านโทเคนของ Anthropic (ต.ค. 2569) Opus 5.5 = $4 เข้า / $20 ออก · ถ้ารุ่นสำรองตอบ คิดตามรุ่นที่แพงกว่า · รุ่นที่ไม่รู้จักคิดสูงสุด
- ผิดพลาด: กุญแจผิด/ไม่มีสิทธิ์/เครดิตหมด/เรียกถี่/ขัดข้อง → ข้อความไทยบอกวิธีแก้ · บันทึกการใช้ก่อนตอบ (ไม่ throw เพื่อไม่ให้ทรานแซกชันของคำขอย้อนรายการ)
- ชุดทดสอบใช้ client จำลอง (`setAiClientFactory`) ไม่เรียก API จริง

## ยังไม่ได้ทดสอบ

การอ่านบิลจริงกับ Claude (ยังไม่มีกุญแจของกิจการในเครื่องนี้) — หลังเจ้าของใส่กุญแจ ให้ลองบิลจริง 3–5 ใบ ตรวจความถูกต้องและค่าใช้จ่ายต่อใบที่หน้าตั้งค่า
