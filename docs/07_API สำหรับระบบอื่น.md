# API สำหรับระบบอื่น (T7.5)

ให้ระบบอื่น (หน้าร้าน เว็บขายของ โปรแกรมเงินเดือน ระบบคลัง ฯลฯ) อ่าน/บันทึกข้อมูลของบริษัทหนึ่งผ่าน API ชุดเดียวกับที่หน้าจอใช้

## กุญแจ API

- สร้างที่ **เริ่มระบบ › กุญแจ API (เชื่อมต่อระบบอื่น)** (`/settings/api-keys`, เมนู `SET.API` — ระดับอนุมัติ 9 เท่านั้น)
- กุญแจผูกกับ **บริษัทที่เลือกอยู่ตอนสร้าง** + **ผู้ใช้หนึ่งคน** → ทำงานด้วยสิทธิ์ของผู้ใช้นั้นทุกประการ (ระดับอนุมัติ ตารางสิทธิ์ 7 ชนิด) · แนะนำสร้างผู้ใช้เฉพาะระบบแล้วให้สิทธิ์เท่าที่จำเป็น
- ตัวเลือก: อ่านอย่างเดียว (GET เท่านั้น) · วันหมดอายุ
- รูปแบบ `bk_<ส่วนต้น 12 ตัว>_<ส่วนลับ>` — แสดงเต็ม**ครั้งเดียว**ตอนสร้าง ฐานข้อมูลเก็บเฉพาะ SHA-256 ของส่วนลับ (`sys_api_key`, migration 0027) · หายให้ยกเลิกแล้วสร้างใหม่
- ยกเลิก = สถานะ I (ไม่ลบ) ใช้ไม่ได้ทันที · ผู้ใช้ถูกระงับ/ถอนสิทธิ์บริษัท/ลูกค้าหมดอายุ → กุญแจใช้ไม่ได้ทันที
- บันทึกเหตุการณ์: `API_KEY_CREATE` / `API_KEY_REVOKE` · ทุกเอกสารที่บันทึกผ่านกุญแจ log ในนามผู้ใช้ของกุญแจ
- ไม่อยู่ในแฟ้มสำรองข้อมูลบริษัท (สร้างใหม่หลังนำข้อมูลกลับ) และไม่ถูกคัดลอกตอนคัดลอกบริษัท

## การเรียก

```
Authorization: Bearer bk_xxxxxxxxxxxx_yyyyyyyy…
Content-Type: application/json
```

- มี header นี้แล้วใช้กุญแจเสมอ (ไม่ดู cookie) · บริษัทคงที่ตามกุญแจ (`POST /auth/select` ใช้ไม่ได้)
- เงิน = ข้อความทศนิยม (`"1234.50"`) · วันที่ `YYYY-MM-DD` ค.ศ. · บันทึกเอกสาร = ลงบัญชีทันทีเหมือนหน้าจอ · ยกเลิกด้วย `POST …/:id/cancel {reason}`
- ผิดพลาด: `{ "error": { "code", "message", "issues" } }` ภาษาไทย · 401 กุญแจผิด/ยกเลิก/หมดอายุ (บอกเหตุผล) · 403 ไม่มีสิทธิ์/อ่านอย่างเดียว/เมนูต้องห้าม · 429 เกิน 600 ครั้ง/นาที/กุญแจ
- ไม่มี CORS — เรียกจากเซิร์ฟเวอร์/โปรแกรม ไม่ใช่จากหน้าเว็บโดเมนอื่น

## ส่งเอกสารจากระบบอื่น: อ้างอิงต้นทาง + ส่งซ้ำไม่ลงซ้ำ (WTS Connect v1 · docs/17 ข้อ 3.1)

ส่ง header 3 ตัวกับ API **สร้าง**เอกสาร/ใบสำคัญ (POST ที่ไม่มี `:id` เช่น `/api/v1/cash-sales`, `/api/v1/gl/journals`) — ใช้ได้เฉพาะคำขอที่ใช้กุญแจ API

```
X-Source-System: wts-pos            (a-z 0-9 - ยาว 2–30)
X-Source-Ref: pos:BK01:2026-10-15:HS (≤ 100 ตัว ไม่ซ้ำในบริษัทต่อระบบ)
X-Source-Version: 1                  (จำนวนเต็ม ไม่ส่ง = 1)
```

| สถานการณ์ | ผล |
|---|---|
| ยังไม่มีเลขอ้างอิงนี้ | สร้าง → **201** + `id` `doc_no`/`voucher_no` `source_*` |
| มีแล้ว รุ่นเท่ากัน | **200** เอกสารเดิม `duplicate: true` (ไม่สร้างซ้ำ) |
| มีแล้ว รุ่นสูงกว่า | แก้เอกสารเดิมด้วย API แก้ไขของเอกสารชนิดนั้น (ใบสำคัญถูกแทน) → **200** `updated: true` · ต้องมีสิทธิ์ "แก้ไข" · งวดปิดแล้ว → **409 `PERIOD_CLOSED`** (ส่งใบปรับปรุงด้วยเลขอ้างอิงใหม่) |
| มีแล้ว รุ่นต่ำกว่า | **409 `STALE_VERSION`** |
| เอกสารถูกยกเลิกใน Buddy | **409 `SOURCE_CANCELLED`** — ลบเอกสารที่ยกเลิกใน Buddy แล้วส่งใหม่ หรือใช้เลขอ้างอิงใหม่ |
| header ผิดรูปแบบ / ไม่ใช้กุญแจ / API ที่ไม่สร้างเอกสาร | **400 `BAD_SOURCE`** |

- **ตรวจยอดต้นทาง (B0.2):** ใส่ `source_totals` ในเนื้อคำขอ = ยอดที่ต้นทางคำนวณ · Buddy บันทึกแล้วเทียบในทรานแซกชันเดียวกัน ต่างแม้ 0.01 → **422 `AMOUNT_MISMATCH`** (ไม่บันทึกอะไรเลย · `issues` บอกช่อง ยอดต้นทาง ยอด Buddy ผลต่าง) · ห้ามปัดให้ตรงเงียบ ๆ
  - เอกสาร: `net_amount` (สุทธิรวม VAT) · `taxable_amount` (ก่อน VAT = สุทธิ − VAT) · `vat_amount` · `wht_amount`
  - ใบสำคัญ: `total` (ยอดรวมเดบิต = เครดิต)
  - เช่น `"source_totals": { "net_amount": "30000.00", "taxable_amount": "28037.38", "vat_amount": "1962.62" }`
- **ใบกำกับภาษีอย่างย่อจาก POS (B0.4):** ขายสดรวมยอดรายวัน (`POST /api/v1/cash-sales`) ส่ง `abbr_invoices` = 1 บรรทัดต่อเครื่อง `{ pos_device_code, inv_from, inv_to, inv_count, base_amount, vat_amount, exempt_amount }` (มูลค่าไม่รวม VAT) · ยอดรวมทุกเครื่องต้องเท่าเอกสารทุกสตางค์ ไม่งั้น 400 · รายงานภาษีขายแสดง 1 บรรทัดต่อเครื่อง "ใบกำกับภาษีอย่างย่อ เลขที่ x–y" · บิลที่ออกใบกำกับเต็มรูปใน POS ไม่รวมในยอดนี้ ส่งเป็น HS/IV แยกรายใบ (สำนักงานบัญชียืนยันรูปแบบกับประกาศสรรพากร/ภ.พ.06)
- เลขอ้างอิงเดียวกันต่างระบบ หรือต่างบริษัท = คนละเอกสาร
- เอกสารที่มี `source_system` แสดงป้าย "มาจาก WTS-POS · อ้างอิง …" · **แก้/ยกเลิก/ลบที่หน้าจอ Buddy หรือด้วยระบบอื่นไม่ได้** (**403 `SOURCE_LOCKED`**) — ระบบต้นทางยกเลิกเองได้โดยส่ง `X-Source-System` เดียวกันกับ `POST …/:id/cancel` · ผู้ใช้ระดับอนุมัติ 9 ยกเลิก/ลบได้พร้อมเหตุผล (log `SOURCE_OVERRIDE`)
- พิมพ์ · บันทึกเลขที่ 50 ทวิ ที่ได้รับ · ลงบัญชีใหม่ · คัดลอกเป็นใบใหม่ ทำได้ตามปกติ
- เครื่องสาขาออฟไลน์ไม่รับ — ส่งเข้าเครื่องสำนักงานใหญ่

## มัดจำรับ: ใบเสร็จหักมัดจำ + คืนเงินมัดจำ (WTS-Living ย้ายออก · 05/11/2569)

ใช้กับเงินประกัน/มัดจำที่รับด้วย `POST /api/v1/ar-deposits` (AI) — ใบเสร็จ (ข้อ 1) หักได้เฉพาะมัดจำ**ที่ไม่มี VAT** (`vat_amount` = 0) · ใบคืนเงินมัดจำ (ข้อ 2) คืนมัดจำที่มี VAT ได้ = ใบลดหนี้ (ข้อ 3 · 06/11/2569) · ส่ง `X-Source-*` และ `source_totals` ได้เหมือนเอกสารอื่น

**1) ใบเสร็จรับเงินชำระด้วยมัดจำ** — `POST /api/v1/ar-receipts` (แก้ `PUT /api/v1/ar-receipts/:id`) เพิ่มช่อง

```json
"deposits": [{ "header_id": "<id ของ AI>", "amount": "4547.16" }]
```

- ยอดชำระจริง = เงินสด (`cash_amount` ว่าง = ส่วนที่เหลือ) + `payments` + มัดจำที่หัก → ชำระด้วยมัดจำทั้งหมดได้ (เงินสด 0)
- ตรวจ: AI ของลูกค้าเดียวกัน บริษัทเดียวกัน ไม่ยกเลิก ลงวันที่ไม่หลังใบเสร็จ ยอด > 0 และไม่เกินคงเหลือ (แก้ใบเดิม = นับยอดที่ใบนั้นหักไว้กลับ) · ใบสำคัญจ่าย (`ap-payments`) ส่ง `deposits` ไม่ได้
- ลงบัญชี: Dr เงินมัดจำรับล่วงหน้า (บัญชีช่อง 3 ของประเภทเอกสาร AI → บัญชีเพื่อลงรายวัน `DEPOSIT_RECEIVED`) / Cr ลูกหนี้ · บิลภาษีเกณฑ์เงินสด: Dr ภาษีขายรอเรียกเก็บ / Cr ภาษีขาย (ใบเสร็จนี้คือการรับชำระ — ภาษีถึงกำหนดเหมือนรับเงิน และเข้าแฟ้มภาษีขาย)
- ผลลัพธ์มี `deposit_amount` · `GET /api/v1/ar-receipts/:id` มี `deposits[] { header_id, doc_no, doc_date, amount, outstanding }` · พิมพ์แสดง "หักเงินมัดจำ" ในส่วนชำระ
- `source_totals.net_amount` = ยอดบิลที่ตัด (ไม่ใช่ยอดเงินสด)

**2) คืนเงินมัดจำ (RD)** — Express ไม่มีเอกสารนี้ Buddy เพิ่มเป็นหมวดเอกสาร `RD` (ประเภทเอกสาร/เลขที่ `RD…` สมุดรายวันจ่าย)

```
GET  /api/v1/ar-deposit-refunds            (q from to party_id status type_id)
GET  /api/v1/ar-deposit-refunds/:id
POST /api/v1/ar-deposit-refunds            PUT /api/v1/ar-deposit-refunds/:id
POST /api/v1/ar-deposit-refunds/:id/cancel { "reason": "…" }
POST /api/v1/ar-deposit-refunds/posting-preview
```

```json
{ "doc_type_id": "<ประเภทเอกสารหมวด RD — GET /api/v1/trade-defaults/RD>", "doc_date": "2026-07-31", "party_id": "<ลูกค้า>",
  "deposits": [{ "header_id": "<id ของ AI>", "amount": "4752.84" }],
  "payments": [{ "payment_method_id": "<วิธีจ่ายชำระ direction P เช่น โอน>", "amount": "4752.84", "reference_no": null }],
  "cash_amount": null, "your_ref": "ย้ายออกห้อง 101", "remark": null, "department_id": null, "salesperson_id": null,
  "source_totals": { "net_amount": "4752.84" } }
```

- ยอดคืน = รวม `deposits[].amount` = เงินสด + `payments` (ว่าง `payments` = คืนเป็นเงินสดทั้งหมด) · ตรวจเหมือนข้อ 1 (ต้องเลือกอย่างน้อย 1 ใบ)
- ลงบัญชี: Dr เงินมัดจำรับล่วงหน้า (ตามใบมัดจำ) / Cr เงินสด (ช่อง 3 ของประเภทเอกสาร RD → `CASH`) หรือบัญชีของวิธีจ่าย/เช็คจ่าย
- ยกเลิก = สถานะ C ยอดมัดจำกลับเป็นคงเหลือ · ใบที่ส่งมาด้วย `X-Source-System` ยกเลิกจากต้นทางด้วยระบบเดียวกัน

**3) คืนมัดจำที่มี VAT = ใบลดหนี้ (06/11/2569 · เจ้าของ "คืนเงินมัดจำที่มี VAT ด้วยใบลดหนี้")** — ใช้ endpoint เดียวกับข้อ 2

- `deposits[].amount` = ยอดคืน**ในหน่วยของใบมัดจำ** (ไม่เกิน `outstanding`): AI แยก VAT (`price_type` 2) = มูลค่าก่อน VAT · AI รวม VAT (1) = ยอดรวม VAT
- ต่อใบมัดจำ: แยก VAT → ก่อน VAT = ยอดคืน, VAT = ปัด 2 ตำแหน่ง(ยอดคืน × อัตรา / 100), เงินที่จ่าย = ยอดคืน + VAT · รวม VAT → ก่อน VAT = ปัด(ยอดคืน × 100 / (100 + อัตรา)), VAT = ยอดคืน − ก่อน VAT, เงินที่จ่าย = ยอดคืน
- **ปิดยอดตรงสตางค์:** ใบที่ทำให้คงเหลือเป็น 0 และใบมัดจำไม่ถูกใช้ในเอกสารอื่นนอกจากใบคืนเงิน → VAT = VAT ของใบมัดจำ − VAT ของใบคืนเงินอื่นที่ยังใช้ (ตัวอย่าง: มัดจำรวม VAT 1,000 (VAT 65.42) คืน 333 → VAT 21.79 · คืน 667 → VAT 43.63 ไม่ใช่ 43.64) · VAT ต่อใบมัดจำเก็บที่ `doc_link.vat_amount` (migration 0056)
- ใบเดียวกัน: ไม่มี VAT ทั้งหมด **หรือ** มี VAT ประเภทราคา/อัตราเดียวกันทั้งหมด — ปนกันได้ 400 "…ให้แยกเป็นใบคืนเงินมัดจำคนละใบ"
- **`remark` = เหตุผลที่ลดหนี้ (บังคับเมื่อมี VAT)** เช่น "ยกเลิกสัญญา คืนเงินมัดจำ" — พิมพ์ในใบลดหนี้
- **`etax_purpose_code` = รหัสเหตุผลใบลดหนี้ e-Tax (HANDOFF ข้อ 90 · docs/19 ข้อ 8)** — เลือกได้จากรายการมาตรฐาน ETDA: สินค้า `CDNG01` ลดราคาสินค้าที่ขาย (สินค้าผิดข้อกำหนดที่ตกลงกัน) · `CDNG02` สินค้าชำรุดเสียหาย · `CDNG03` สินค้าขาดจำนวนตามที่ตกลงซื้อขาย · `CDNG04` คำนวณราคาสินค้าผิดพลาดสูงกว่าที่เป็นจริง · `CDNG05` รับคืนสินค้า (ไม่ตรงตามคำพรรณนา) · `CDNG99` เหตุอื่น (ระบุสาเหตุ) · บริการ `CDNS01` ลดราคาค่าบริการ (บริการผิดข้อกำหนดที่ตกลงกัน) · `CDNS02` ค่าบริการขาดจำนวน · `CDNS03` คำนวณราคาค่าบริการผิดพลาดสูงกว่าที่เป็นจริง · `CDNS04` บอกเลิกสัญญาบริการ · `CDNS99` เหตุอื่น (ระบุสาเหตุ)
  · ว่าง/ไม่ส่ง = `CDNS04` (ค่าเช่า/บริการ เช่น WTS-Living) · มัดจำค่าสินค้าแนะนำ `CDNG99` · รหัสลงท้าย 99 ต้องมี `remark` · รหัสอื่นนอกรายการ 400 "…ไม่อยู่ในรายการมาตรฐาน ETDA…" · มัดจำไม่มี VAT ไม่เก็บรหัส (`null`) · เก็บที่ `doc_header.etax_purpose_code` (migration 0059) · ใบเดิมก่อน 0059 (ว่าง) = `CDNS04` · e-Tax XML `PurposeCode` และใบพิมพ์ "เหตุผลที่ลดหนี้: <รหัส> <ชื่อ> — <remark>" ใช้รหัสนี้
- ยอดจ่ายจริง (เงินสด + `payments`) = รวมเงินที่จ่าย (รวม VAT) · `source_totals.net_amount` = ยอดนี้ · ผลลัพธ์มี `net_amount` และ `vat_amount`
- หัวเอกสาร: `price_type`/`vat_rate` ตามใบมัดจำ · `vat_amount` = VAT รวม · `taxable_amount` = รวมยอดคืน (รวม VAT: แฟ้มภาษีหัก VAT ออก → มูลค่า = ก่อน VAT รวม) · `net_amount` = เงินที่จ่าย · `ref_no`/`ref_date` = ใบมัดจำใบแรก · `GET :id` มี `deposits[].vat_amount`
- ลงบัญชี: Dr เงินมัดจำรับ (ก่อน VAT ต่อใบมัดจำ) + Dr ภาษีขาย (`OUTPUT_VAT`) / Cr เงินสด/วิธีจ่าย (เงินที่จ่าย) — มัดจำไม่มี VAT ลงเหมือนเดิมทุกบรรทัด
- แฟ้ม/รายงานภาษีขาย: รายการ**ติดลบ**แบบใบลดหนี้ เลขที่/วันที่ใบกำกับ = เลขที่/วันที่ RD · งวด = เดือนของ RD · คำอธิบาย "ลดหนี้ — คืนเงินมัดจำ <ลูกค้า> อ้างถึงใบกำกับภาษี AI… ลว. …" (ทุกใบมัดจำ) · รายงานแยกชนิดเอกสาร = กลุ่ม "ใบลดหนี้ — คืนเงินมัดจำ" · ยกเลิก RD = รายการภาษีสถานะยกเลิก
- พิมพ์: ชื่อ "ใบลดหนี้ / ใบคืนเงินมัดจำ" · รายการ = ใบกำกับภาษีเดิม (AI) เลขที่ วันที่ มูลค่า ภาษี และมูลค่า/ภาษีที่ลด · ยอด: มูลค่าตามใบกำกับภาษีเดิม (ลดหนี้ครั้งก่อน) มูลค่าที่ถูกต้อง ผลต่าง ภาษีของผลต่าง รวมเงินคืน · หมายเหตุ "เหตุผลที่ลดหนี้: <รหัส e-Tax> <ชื่อ> — …"
- `GET /api/v1/deposits/open` เพิ่ม `price_type` `vat_rate` `rd_vat` (VAT ของใบคืนเงินอื่น) `other_use` (มีบิล/ใบเสร็จใช้อยู่) ให้หน้าจอคำนวณแบบเดียวกัน · e-Tax XML: RD ที่มี VAT ส่งออกเป็น 81 ใบลดหนี้ อ้าง AI ทุกใบ (T03) ที่ `GET /api/v1/etax/doc/:id` และ `/etax/export` (HANDOFF ข้อ 89 · docs/08)
- ระบบอื่น: WTS-POS (`vat_refund_unsupported`) เปลี่ยนมาส่ง RD แทนได้ภายหลัง

**ยอดคงเหลือ** — `GET /api/v1/deposits/open?module=AR&party_id=…` (`invoice_id` = เอกสารที่กำลังแก้) คืน `outstanding` และ `vat_amount` ของแต่ละ AI · `GET /api/v1/ar-deposits/:id` มี `remaining` และ `used_by[]` (บิล ใบเสร็จ ใบคืนเงิน) · ใบมัดจำที่ถูกหัก/คืนอยู่ ยกเลิกหรือลบไม่ได้

**กฎภาษี (เลือกแบบปลอดภัยที่สุด):** มัดจำที่มี VAT ภาษีถึงกำหนดแล้วตอนรับมัดจำ — ถ้าหักในใบเสร็จที่ตัดบิลภาษีเกณฑ์เงินสด ภาษีจะถึงกำหนดซ้ำ จึงต้องหักในบิลขาย (IV/HS แท็บหักเงินมัดจำ) ตามเดิม · การคืนมัดจำที่มี VAT ทำด้วยใบคืนเงินมัดจำ = ใบลดหนี้ (ข้อ 3) — ให้สำนักงานบัญชียืนยันกรณีคืนมัดจำเมื่อยกเลิกสัญญา

## ฟีดข้อมูลหลักที่เปลี่ยน (WTS Connect v1 · docs/17 ข้อ 3.3 · B0.3)

```
GET /api/v1/changes?types=item,customer,supplier,branch,warehouse,payment_method,bank_account,doc_type,unit,account,department&since=<next_cursor>&limit=1000
```

- ใช้กุญแจอ่านอย่างเดียวได้ · สิทธิ์เท่าหน้าต่างค้นหา · เห็นเฉพาะบริษัทของกุญแจ
- ไม่ส่ง `since` (หรือ 0) = ข้อมูลทั้งหมดของชนิดที่ขอ (`full: true`) — ใช้ครั้งแรก และปุ่ม "ดึงข้อมูลใหม่"
- ส่ง `since` = `next_cursor` ครั้งก่อน → เฉพาะแถวที่เปลี่ยน · `more: true` = ยังมีต่อ เรียกซ้ำทันทีด้วย cursor ใหม่
- `changes[]` = `{ type, id, op, data }` · `op: "upsert"` ค่าปัจจุบัน (`status: "I"` = เลิกใช้) · `op: "delete"` + `data: null` = ถูกลบ ให้ลบสำเนา · แถวเดียวกันเปลี่ยนหลายครั้งได้ครั้งเดียว (ค่าล่าสุด)
- ช่องที่ส่ง: เฉพาะที่โปรแกรมอื่นใช้ (รหัส ชื่อ หน่วย ราคา 1–5 รหัสภาษี เลขผู้เสียภาษี สาขา สถานะ ฯลฯ — ดู `CHANGE_TYPES` ใน `apps/server/src/modules/changes.ts`) · อ้างถึงกันด้วย `id` (เช่น `sales_unit_id` → ชนิด `unit`)
- รายการที่เพิ่งเปลี่ยนไม่ถึง 3 วินาทียังไม่ส่ง (รอให้บันทึกที่ทำพร้อมกันเสร็จ จะได้ไม่ข้าม) — แนะนำดึงทุก 1–5 นาที
- `payment_method` มี `gl_account_id` / `bank_account_id` (บัญชีที่วิธีชำระผูกไว้) · `bank_account` = บัญชีเงินฝาก (รหัส ชื่อ เลขที่บัญชี ชนิด `gl_account_id` สกุลเงิน) ใช้เลือกบัญชีนำฝาก/ช่องทางรับเงิน (04/11/2569)
- `item` มี `default_supplier_id` (ผู้จำหน่ายหลัก → ชนิด `supplier`) และ `std_cost` (ราคาทุนมาตรฐาน) — WTS-POS ใช้ทำแผนซื้อครัวกลางแยกผู้จำหน่าย + ราคาใน PO (B3.3, 04/11/2569) · ปุ่ม "ตั้งค่าสำหรับ WTS-POS" สร้างประเภทเอกสารผลิตครัวกลาง `OUP` (หมวด OU เบิกวัตถุดิบ = PD) และ `JUP` (หมวด JU รับสินค้าผลิตเสร็จ = PI) ด้วย

- **ช่องเพิ่มเติม (06/11/2569 · HANDOFF ข้อ 86 — เพิ่มอย่างเดียว ของเดิมไม่เปลี่ยน โปรแกรมที่ไม่ใช้ช่องใหม่ไม่กระทบ):**
  - `doc_type` มี `accounts: [{ slot, role, account_id }]` (บัญชีที่ประเภทเอกสารกำหนดไว้ เช่น AI ช่อง 3 `DEPOSIT_RECEIVED`) + `vat_basis` (1 เกณฑ์สิทธิ 2 เกณฑ์เงินสด) + `journal_book_id` · แก้บัญชีของประเภทเอกสารอย่างเดียวก็ได้แถว `doc_type` ใหม่ในรอบถัดไป
  - `item` มี `revenue_account_id` (บัญชีรายได้ของรหัสบริการ/กลุ่มบัญชีสินค้า · ว่าง = ใช้บัญชีตามการเชื่อมต่อบัญชี) · แก้บัญชีของกลุ่มอย่างเดียวก็ได้แถว `item` ใหม่
  - ชนิดใหม่ `default_account` = บัญชีตามบทบาท `{ role, account_id }` (เช่น `CASH` `AR` `OPENING_BALANCE` บัญชีพักยอดยกมา) · `journal_book` = สมุดรายวัน `{ code, prefix, name_th, name_en }`
  - Buddy รุ่นเก่าตอบ 400 "ไม่รู้จักชนิด" สำหรับชนิดใหม่ — ขอชนิดเดิมต่อตามปกติแล้วลองใหม่ภายหลัง (แบบ WTS-Living `OPTIONAL_TYPES`)

## ยอดยกมาที่ลงบัญชี: ลูกหนี้/เงินประกันยกมาจากระบบอื่น (06/11/2569 · HANDOFF ข้อ 86)

```
POST /api/v1/ar-opening           { party_id, doc_no, doc_date, price_type, amount, vat_rate, vat_amount?, doc_type_id?, post_gl: true, offset_account_id? }
POST /api/v1/ar-deposit-opening   { party_id, doc_no, doc_date, price_type: "0", amount, vat_rate: "0", doc_type_id?, post_gl: true, offset_account_id? }   (ใบมัดจำรับ AI ยกมา — ใหม่)
```

- `post_gl` ไม่ส่ง/false = แบบเดิม (ทะเบียนอย่างเดียว ไม่ลงบัญชี · วันที่ต้องก่อนวันเริ่มใช้ · ยอดบัญชีป้อนที่บันทึกยอดยกมา)

  - ลูกหนี้ยกมา: Dr ลูกหนี้ (ประเภทเอกสาร → ลูกค้า → `AR`) / Cr บัญชีคู่ — ยอดค้างรวม VAT · ไม่มีบรรทัดภาษี ไม่เข้าแฟ้มภาษี (ภาษีขายรอเรียกเก็บของบิลยกมาอยู่ในยอดยกมาเดิมแล้ว — ลงซ้ำ = นับสองครั้ง) · VAT ถึงกำหนดตอน RE ตามปกติ
  - วิธีใช้กับบันทึกยอดยกมาทั้งชุด: ยอดลูกหนี้/เงินประกันที่ระบบอื่นส่งเข้า ให้ใส่ที่บัญชีพักยอดยกมาแทนบัญชีลูกหนี้/เงินประกัน (บัญชีอื่นรวมภาษีขายรอเรียกเก็บใส่ตามเดิม) → หลังระบบอื่นส่งครบ บัญชีพักยอดยกมา = 0
  - มัดจำยกมา: Dr บัญชีคู่ / Cr เงินมัดจำรับ (ช่อง 3 ของประเภทเอกสาร AI) · หัก (RE `deposits`) / คืน (RD) ได้เหมือนใบมัดจำปกติ · มี VAT ไม่รับ
  - ลงวันที่ก่อนวันเริ่มใช้ = ยอดยกมาในงบทดลอง · ตั้งแต่วันเริ่มใช้ = ใบสำคัญของงวดนั้น (ต้องยังไม่ปิด — ระบบอื่นเริ่มใช้ทีหลัง Buddy)
- เจ้าหนี้ยกมา (`ap-opening`) ไม่รับ `post_gl`

## เพิ่มวิธีรับ/จ่ายชำระทีละรายการ (WTS-POS ช่องทางรับเงิน · 04/11/2569)

```
POST /api/v1/payment-methods/R   { code: "LP", name_th: "LINE Pay", name_en?, kind: "OTHER", gl_account_id?: uuid, bank_account_id?: uuid, seq?: "05" }
→ 201 { id, code }
```

- เพิ่ม 1 รายการ ไม่แตะรายการเดิม (ต่างจาก `PUT` ที่บันทึกทั้งชุดของหน้าจอ) · `R` = วิธีรับชำระ · `P` = วิธีจ่ายชำระ · สิทธิ์ = เมนูวิธีรับ-จ่ายชำระ (SET.PAYM) "เพิ่ม" — กุญแจอ่านอย่างเดียวใช้ไม่ได้

- แนะนำ: QR พร้อมเพย์/โอน → `TRANSFER` + บัญชีเงินฝาก · บัตร → `CARD` + บัญชีพักบัตร · e-Wallet (Stripe PayPal LINE Pay TrueMoney ฯลฯ) → `OTHER` + บัญชีพักของผู้ให้บริการนั้น

- `key`: `buddy` `pos` `living` `hr` `hotel` `spa` · `active` = เปิดและยังไม่เลยวัน `valid_to` (ใช้ได้ถึงสิ้นวันนั้น) — Hub แสดงไทล์ / โปรแกรมอื่นตรวจสิทธิ์ก่อนทำงาน
- ใช้ session ผู้ใช้หรือกุญแจ API ก็ได้ · เห็นเฉพาะลูกค้าของตัวเอง
- เจ้าหน้าที่ผู้ให้บริการตั้งค่าที่ ลูกค้าผู้ใช้บริการ › แก้ไขลูกค้า › โปรแกรมที่ลูกค้าใช้ได้ (`PUT /api/v1/tenants/:id/modules`) · มีช่อง `app_url` = ที่อยู่หน้าเว็บของโปรแกรมสำหรับลูกค้านั้น (Hub เปิดที่นี่)

## Hub + ล็อกอินกลาง: บัตรผ่าน (docs/17 ข้อ 5.8 · B6.1 · 05/11/2569)

ผู้ใช้ล็อกอิน Buddy ครั้งเดียว กดไทล์ใน Hub แล้วเข้าโปรแกรมอื่นได้เลย ไม่ต้องใส่รหัสผ่านซ้ำ · โปรแกรมเก็บล็อกอินของตัวเองไว้ใช้ตอนใช้แบบแยก/Buddy ล่ม (D9 D11)

```
GET  /.well-known/jwks.json  (หรือ /api/v1/sso/jwks)  → { keys: [{ kty:"OKP", crv:"Ed25519", x, kid, alg:"EdDSA", use:"sig" }] }   ไม่ต้องเข้าระบบ
POST /api/v1/hub/launch { module: "pos" }   (session ผู้ใช้เท่านั้น)  → { url: "<app_url>#buddy_sso=<JWT>", expires_in: 120 }
```

1. Hub เปิด `url` ในแท็บใหม่ — บัตรอยู่หลัง `#` จึงไม่ถูกส่งไปเซิร์ฟเวอร์และไม่ลง log ของเว็บ
2. หน้าเว็บของโปรแกรมอ่าน `#buddy_sso=` แล้ว **ลบออกจากแถบที่อยู่ทันที** (`history.replaceState`) ส่งบัตรไปเซิร์ฟเวอร์ของโปรแกรม (POST) เพื่อเปิด session ของโปรแกรมเอง
3. เซิร์ฟเวอร์ของโปรแกรมตรวจ (ห้ามข้ามข้อใด):
   - ลายเซ็น EdDSA (Ed25519) กับกุญแจใน JWKS **ของ Buddy ที่บริษัทนั้นผูกไว้** (ที่อยู่ Buddy เดียวกับที่ใช้ส่งเอกสาร) · `kid` ไม่รู้จัก = ดึง JWKS ใหม่ 1 ครั้ง · เก็บ JWKS ไว้ได้ (Buddy ล่มแต่มี JWKS เดิม = ยังตรวจได้)
   - `aud` = ชื่อโปรแกรมตัวเอง (`wts-pos` `wts-living` `wts-hotel` `wts-spa` `wts-sop`)
   - `exp` ยังไม่หมด (เผื่อนาฬิกาคลาด ≤ 60 วินาที) · อายุบัตร 120 วินาที
   - `jti` ยังไม่เคยใช้ — จดไว้จนเลย `exp` (บัตรใช้ได้ครั้งเดียว)
   - `buddy.company.id` ตรงกับรหัสบริษัท Buddy ที่โปรแกรมผูกไว้ (อ่านจาก `GET /api/v1/auth/me` ด้วยกุญแจของบริษัท → `company.id`) · ไม่ตรง = ไม่รับ (ห้ามเชื่อชื่อ/รหัสบริษัทในบัตรอย่างเดียว)
4. ผู้ใช้: ผูกด้วย `sub` (รหัสผู้ใช้ Buddy — ไม่เปลี่ยน) ห้ามผูกด้วยชื่อผู้ใช้ · ครั้งแรกสร้างผู้ใช้ในโปรแกรมได้ สิทธิ์ในโปรแกรมเป็นของโปรแกรมเอง (`buddy.admin` = ผู้ดูแลลูกค้าใน Buddy ใช้เป็นค่าตั้งต้นได้)

เนื้อบัตร (payload):

```json
{ "iss": "https://buddy.example.com", "aud": "wts-pos", "sub": "<id ผู้ใช้ Buddy>", "iat": 1793860000, "exp": 1793860120, "jti": "<uuid>",
  "name": "สมชาย ใจดี", "preferred_username": "somchai",
  "buddy": { "tenant": { "id": "…", "code": "DEFAULT", "name": "…" },
             "company": { "id": "…", "code": "BK", "name_th": "บริษัท บีเค จำกัด", "tax_id": "0105…" },
             "branch": { "id": "…", "code": "00000", "name": "สำนักงานใหญ่" } | null,
             "admin": true, "platform": false } }
```

- ออกบัตรได้เมื่อ: ลูกค้าเปิดใช้โปรแกรมนั้นและยังไม่หมดอายุ (B0.6) + ผู้ให้บริการตั้ง `app_url` แล้ว · ไม่เปิด = 403 · ไม่มีที่อยู่ = 409 `APP_URL_MISSING` · กุญแจ API ขอบัตรไม่ได้ · ทุกครั้งบันทึก `HUB_LAUNCH` ใน log (jti)
- `iss` = `BUDDY_PUBLIC_URL` (ว่าง = ที่อยู่ที่ผู้ใช้เปิด Buddy) — ใช้แสดงเท่านั้น ความน่าเชื่อถืออยู่ที่ลายเซ็น + JWKS ของ Buddy ที่ผูกไว้
- กุญแจลงนามได้จากกุญแจหลักของเครื่องแม่ข่าย (`.data/secret.key` / `BUDDY_SECRET_KEY`) — เปลี่ยนกุญแจหลัก = `kid` ใหม่ โปรแกรมดึง JWKS ใหม่เอง
- ตัวอย่างการตรวจ (node:crypto ไม่ต้องติดตั้งแพ็กเกจ): `verifySsoToken` ใน `apps/server/src/sso.ts`

## รายงานคิวส่งเอกสารให้ Hub (SyncStatus · B6.2)

```
PUT /api/v1/source-status   (กุญแจ API ของบริษัท ที่บันทึกได้)
{ "system": "wts-pos", "pending": 3, "failed": 0, "oldest_pending_at": "2026-11-05T13:40:00+07:00" | null,
  "last_sent_at": "2026-11-05T14:02:00+07:00" | null, "message": "ข้อความไทยของรายการที่ไม่ผ่าน" | null,
  "metric": { "label": "ยอดขายวันนี้", "value": "12345.00" } | null }
→ { ok: true, state: "online" | "syncing" | "error" }
```

- ส่งทุก 1–5 นาที และหลังคิวเปลี่ยน · แถวเดียวต่อบริษัทต่อ `system` เขียนทับ · ไม่ลง log (เป็นสถานะชั่วคราว)
- Hub: ส่งไม่ผ่าน > 0 = ❌ · ไม่ได้รับรายงานเกิน 15 นาที = "ไม่ได้รับสถานะ" · รอส่ง > 0 = กำลังซิงก์ · ไม่งั้น = ปกติ · `metric` แสดงบนไทล์ (เงินเป็นข้อความทศนิยม)
- **ส่งไม่ได้ต้องไม่กระทบงานหน้าร้าน** (D11) — ล้มเหลวก็ข้ามไป รอรอบถัดไป

## พิมพ์เอกสารที่ระบบตัวเองส่งเข้ามา: ใบกำกับภาษี RE (06/11/2569 · HANDOFF ข้อ 87 · docs/19 ข้อ 3)

ใบกำกับภาษีของค่าเช่า/ค่าบริการ WTS-Living = **ใบเสร็จรับเงิน/ใบกำกับภาษี (RE) ของ Buddy** — ระบบต้นทางดึงเอกสารพิมพ์ไปออก PDF ให้ผู้เช่า

```
GET /api/v1/docs/:id/print            (กุญแจ API เท่านั้น · :id = id ที่ Buddy ตอบตอนส่งเอกสาร)
X-Source-System: wts-living           (ต้องส่ง เว้นแต่กุญแจขอบเขต A)
→ { data: <ข้อมูลพิมพ์ชุดเดียวกับหน้าพิมพ์ของ Buddy>, copy: "ต้นฉบับ" | "สำเนา", doc_status: "N" | "C", logo: data-URL | null }
```

- `data` = `GET /api/v1/print/doc/:id` ของหน้าจอ: `title` (`ใบเสร็จรับเงิน/ใบกำกับภาษี` เมื่อ RE ตัดบิลภาษีเกณฑ์เงินสดที่มี VAT · ไม่มี VAT = `ใบเสร็จรับเงิน`) `company` (ชื่อ ที่อยู่ เลขผู้เสียภาษี สำนักงานใหญ่/สาขา) `party` (ชื่อ ที่อยู่ เลขผู้เสียภาษี สาขา) `doc_no` `doc_date` `fields.payment_date` `detail` (บิลที่ชำระ + รายการบริการ จำนวน × ราคา มูลค่า) `totals` (มูลค่าที่มี VAT · ภาษีมูลค่าเพิ่ม n% · มูลค่าที่ไม่มี VAT · ยอดสุทธิ) `amount_text` `payments` `source_system`
- **ขอบเขตของกุญแจ** (`sys_api_key` migration 0058 · ตั้งที่หน้ากุญแจ API ปุ่ม "ระบบ" / ตอนสร้าง · `PUT /api/v1/api-keys/:id/scope { source_system, doc_scope }` log `API_KEY_SCOPE`):
  - `doc_scope` **S** (ค่าเริ่มต้น) = เฉพาะเอกสารที่ `source_system` ตรงกับ `X-Source-System` · **A** = ทุกเอกสารของบริษัท (ตามสิทธิ์ผู้ใช้)
  - `source_system` ตั้งแล้ว → `X-Source-System` อื่น = **403 `SOURCE_MISMATCH`** · ว่าง = ตามที่คำขอส่งมา
- บริษัทของกุญแจเท่านั้น · เอกสารของบริษัทอื่น/ระบบอื่น/ที่คีย์ใน Buddy/ไม่มี = **404** (ไม่บอกว่ามีอยู่) · ไม่ส่ง `X-Source-System` (ขอบเขต S) = **400 `BAD_SOURCE`** · ใช้ cookie (หน้าจอ) = 400
- สิทธิ์ "พิมพ์" ของเมนูเอกสารนั้น · ทำตามกฎรับรองก่อนพิมพ์/พิมพ์ซ้ำของประเภทเอกสาร (**409 `PRINT_BLOCKED`**) · ผู้ใช้สิทธิ์พิมพ์ออกจอเท่านั้น = 403
- **ไม่แก้เอกสาร/บัญชี** — นับครั้งที่พิมพ์เหมือนปุ่มพิมพ์ของ Buddy (ครั้งแรก `copy` = ต้นฉบับ ต่อไป = สำเนา) + log `PRINT`/`REPRINT` `{ via: "api", system, copy }`
- Buddy ไม่มีตัวสร้าง PDF ฝั่งเซิร์ฟเวอร์ (พิมพ์จากเบราว์เซอร์) → ระบบต้นทางวาด PDF จาก `data` เอง (WTS-Living: pdfkit + ฟอนต์ไทย) ห้ามเปลี่ยนตัวเลข/ชื่อเอกสาร
