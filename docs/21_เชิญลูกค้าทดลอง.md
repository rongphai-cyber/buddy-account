# เชิญลูกค้าทดลองใช้ Buddy Account

เจ้าของเลือก "เชิญลูกค้าทดลองก่อน" (20/11/2569) — เชิญ 2–5 ราย ก่อนเปิดสมัครทั่วไป
**ตั้งแต่ 24/11/2569 เอาด่าน Cloudflare Access ออกแล้ว** (HANDOFF 184): ลูกค้าเปิดเว็บแล้วเห็นหน้าเข้าระบบ/สมัครของ Buddy ทันที **ไม่ต้องใส่อีเมลลูกค้าที่ Cloudflare อีก** — Buddy เป็นด่านเดียว: ทุกผู้ใช้ต้องตั้งยืนยันตัวตนสองขั้น (แอปในมือถือ) · กล่องกันบอท Turnstile · จำกัดจำนวนครั้ง · ล็อกบัญชีเมื่อรหัสผิด 5 ครั้ง

ทำทีละข้อ จบข้อหนึ่งแล้วค่อยทำข้อถัดไป · คู่มือพร้อมภาพ: `docs/คู่มือรับลูกค้าภายนอก_Buddy.pdf` (ผู้ให้บริการ) และ `docs/คู่มือเริ่มใช้งาน_Buddy_สำหรับลูกค้า.pdf` (ส่งให้ลูกค้า) — ไฟล์ในเครื่องเจ้าของ ไม่อยู่ใน repo

## ก. ก่อนเริ่ม (ทำครั้งเดียว)

1. เข้า https://app.worktruesolution.net ด้วย **รหัสผู้ดูแลระบบที่เจ้าของตั้งตอนตั้งค่าครั้งแรกบนคลาวด์** (ผู้ใช้คนแรกของระบบ = เจ้าหน้าที่ผู้ให้บริการ เห็นทุกลูกค้า) — ใส่รหัส 6 หลักจากแอปยืนยันตัวตน
   - ผู้ใช้ของบริษัทตัวอย่าง (demo.admin, sale1, acc1) **ไม่ใช่** เจ้าหน้าที่ผู้ให้บริการ — อนุมัติใบสมัครไม่ได้ (ระงับไว้แล้ว 24/11/2569)
2. เปิด https://app.worktruesolution.net/admin/tenants (เมนู เริ่มระบบ › ลูกค้าผู้ใช้บริการ) — เห็นแผง "ใบสมัครใช้งาน" ด้านบน = ใช้ได้

## ข. ด่าน Cloudflare Access — เอาออกแล้ว (ไม่ต้องทำอะไรเมื่อเชิญลูกค้าใหม่)

- เอาออกด้วยการเพิ่มนโยบาย **Buddy** (Action **Bypass** · Include **Everyone**) ในแอป **wts-buddy - Cloudflare Workers** ที่ https://one.dash.cloudflare.com/ › Access controls › Applications (มีผล 24/11/2569 23:45)
- **ฉุกเฉิน** (เช่น มีคนพยายามเดารหัสจำนวนมาก): ลบนโยบาย **Buddy** → ด่านอีเมลของ Cloudflare กลับมาทันที (ระหว่างนั้นต้องใส่อีเมลผู้ใช้ในนโยบาย **Buddy trial customers** เหมือนเดิมจึงจะเข้าได้)
- **ห้ามแก้นโยบาย "Thaweechai Sanguanjai"** — ใช้ร่วมกับ POS / Living / wts
- นโยบาย **Buddy trial customers** (Allow · Emails) ยังอยู่ ไม่มีผลขณะที่นโยบาย Buddy เปิดอยู่ — เก็บไว้ใช้ตอนฉุกเฉิน ไม่ต้องเพิ่มอีเมลอีก
- อย่าลบกุญแจ Turnstile (TURNSTILE_SITE_KEY / TURNSTILE_SECRET) — ลบแล้วกล่องกันบอทหาย

## ค. ส่งลิงก์ให้ลูกค้า (ลูกค้าทำเอง)

ส่งข้อความนี้ให้ลูกค้า (หรือส่งไฟล์ `คู่มือเริ่มใช้งาน_Buddy_สำหรับลูกค้า.pdf`):

> 1. เปิด https://app.worktruesolution.net/signup
> 2. กรอกใบสมัคร: ชื่อกิจการ (เป็นชื่อบริษัทแรก) · เลขประจำตัวผู้เสียภาษี (ถ้ามี) · ชื่อ อีเมล โทรศัพท์ · รหัสผู้ใช้ · รหัสผ่าน → ติ๊กยอมรับเงื่อนไข → รอกล่องตรวจของ Cloudflare ขึ้นเครื่องหมายถูก → **ส่งใบสมัคร**
> 3. รอผู้ให้บริการแจ้งว่าอนุมัติแล้ว จากนั้นเข้าระบบที่ https://app.worktruesolution.net ด้วยรหัสผู้ใช้และรหัสผ่านที่ตั้งไว้
> 4. เข้าระบบครั้งแรก ระบบให้ตั้งยืนยันตัวตนสองขั้น: ติดตั้งแอป Google Authenticator หรือ Microsoft Authenticator ในมือถือ → สแกน QR → ใส่รหัส 6 หลัก → เก็บรหัสสำรองไว้

## ง. อนุมัติใบสมัคร (เจ้าของ)

1. เปิด https://app.worktruesolution.net/admin/tenants
2. แผง "ใบสมัครใช้งาน" → แถวของลูกค้า → ปุ่ม **อนุมัติ…**
3. ใส่ **หมดอายุ** = วันสิ้นสุดทดลอง (เช่น อีก 30 วัน) · ช่องอื่นเว้นว่างได้
4. ช่อง **บริษัทแรก** ติ๊กไว้ (ค่าเริ่มต้น) — ระบบสร้างบริษัทชื่อตามใบสมัคร พร้อมผังบัญชีมาตรฐาน ประเภทเอกสาร รอบบัญชีปีนี้ และการลงบัญชีอัตโนมัติ
5. กด **อนุมัติและเปิดบัญชี**
6. แจ้งลูกค้า: "อนุมัติแล้ว เข้าระบบได้ที่ https://app.worktruesolution.net"
   - ลูกค้าเข้าระบบครั้งแรกต้องตั้งยืนยันตัวตนสองขั้นก่อน แล้วเห็นบริษัทของตัวเอง คีย์เอกสารได้ทันที ไม่ต้องให้ผู้ช่วยตั้งค่า
   - ลูกค้าเห็นเฉพาะข้อมูลของตัวเอง เห็นลูกค้ารายอื่นไม่ได้

## จ. ลูกค้าเชิญพนักงานเอง (ผู้ดูแลของลูกค้าทำ — เจ้าของไม่ต้องทำอะไร)

1. ผู้ดูแลของลูกค้าเปิด **เริ่มระบบ › ผู้ใช้งานและสิทธิ์** (https://app.worktruesolution.net/settings/users) → **+ เพิ่มผู้ใช้**
2. ใส่รหัสผู้ใช้ ชื่อ · เลือก **ให้ผู้ใช้ตั้งรหัสผ่านเองจากลิงก์เชิญ** · กลุ่ม/ระดับอนุมัติ · บริษัทที่เข้าได้ → **บันทึก**
3. ได้ลิงก์ + QR → **ส่งทาง LINE** ให้พนักงาน (ใช้ได้ครั้งเดียว ภายใน 72 ชั่วโมง · ออกลิงก์ใหม่ได้)
4. พนักงานเปิดลิงก์ ตั้งรหัสผ่านเอง แล้วตั้งยืนยันตัวตนสองขั้น → เข้าใช้งานได้
   - พนักงานลาออก: สถานะ **ระงับ** · มือถือหาย: **ล้างยืนยันตัวตนสองขั้น** แล้วให้ตั้งใหม่
   - หนึ่งคนหนึ่งบัญชี (แอปยืนยันตัวตนผูกกับมือถือเครื่องเดียว)

## ฉ. ให้ลูกค้าดูข้อมูลตัวอย่างทั้งปี (ดูอย่างเดียว แก้ไม่ได้)

1. เปิด https://app.worktruesolution.net/admin/tenants
2. คลิกแถว **DEMO (ลูกค้าทดลอง บริษัทตัวอย่าง)**
3. เลื่อนลง หัวข้อ "ผู้ใช้ดูอย่างเดียว" → **+ เพิ่มผู้ใช้ดูอย่างเดียว…**
4. ใส่รหัสผู้ใช้เป็นตัวอักษรอังกฤษ (เช่น `demo.shopa`) · ชื่อที่แสดง · รหัสผ่านเริ่มต้น → **เพิ่มผู้ใช้**
5. ส่งรหัสผู้ใช้และรหัสผ่านนี้ให้ลูกค้าทางช่องทางส่วนตัว (LINE/โทร) — **หนึ่งรหัสต่อหนึ่งคน** (ไม่ใช้รหัสร่วม)
   - เข้าครั้งแรกลูกค้าต้องตั้งยืนยันตัวตนสองขั้นด้วยมือถือของตัวเอง
   - ลูกค้าเข้า https://app.worktruesolution.net ด้วยรหัสนี้ = เห็นบริษัทตัวอย่าง เปิดทุกเมนู ดูรายงาน ดูตัวอย่างพิมพ์ทางจอได้
   - ปุ่มบันทึก/ยกเลิก/ลบ กดไม่ได้ · ข้อมูลตัวอย่างไม่เปลี่ยน
   - บริษัทของลูกค้าเอง (ข้อ ง) ยังแก้ไขได้ตามปกติ

## ช. จบการทดลอง

1. เปิด https://app.worktruesolution.net/admin/tenants → คลิกแถวลูกค้า
2. ช่อง **สถานะ** เลือก **ระงับ** → **บันทึก** (ผู้ใช้ของลูกค้าถูกออกจากระบบทันที ข้อมูลยังอยู่ — เปลี่ยนกลับเป็น "ใช้งาน" ได้)
   - หรือใส่ **หมดอายุ** ไว้ตั้งแต่ตอนอนุมัติ ระบบปิดให้เองเมื่อเลยวันนั้น
3. ปิดรหัสดูข้อมูลตัวอย่างของลูกค้ารายนั้น: เลือกบริษัท DEMO แล้วเปิด https://app.worktruesolution.net/settings/users → คลิกรหัส `demo.…` ของลูกค้า → สถานะ **ระงับ** → บันทึก
4. ลูกค้าไม่ใช้ต่อและต้องการลบข้อมูล: สถานะ **เลิกใช้** (ระบบเก็บไว้ 30 วันให้ขอสำเนาก่อนลบ ตาม PDPA)

2. **จำกัดจำนวนครั้งทำงานอยู่** (HANDOFF 165 — เปิดเองเสมอบนคลาวด์ ไม่ต้องตั้ง) ✅
3. **ทุกผู้ใช้ต้องเปิดยืนยันตัวตนสองขั้น** (HANDOFF 184) ✅ — ผู้ที่ยังไม่ตั้งถูกพาไปหน้าตั้งค่าตอนเข้าระบบ · บัญชีที่ยังไม่ตั้งและไม่ได้ใช้ ระงับไว้แล้ว (acc1 sale1 demo.test Ding_WTS demo.admin Admin_test test.staff) — จะเปิดใช้ใหม่ ให้คนนั้นตั้งยืนยันตัวตนทันทีที่เข้าระบบ
4. **รหัสผ่านไม่ง่าย** — โปรแกรมบังคับ ≥ 8 ตัว มีตัวอักษรและตัวเลข · ระงับรหัสทดลองที่ไม่ใช้แล้ว (ข้อ ช)

7. **ตัวเฝ้าระบบ** (README ข้อ 11) ทำงานอยู่ — ถ้าถูกโจมตีจนโปรแกรมช้า/ล่ม จะได้อีเมล
8. แนะนำเพิ่ม (ยังไม่ได้ตั้ง · ที่ Cloudflare › worktruesolution.net): **WAF Rate limiting rule** สำหรับ `/api/v1/auth/` และ `/api/v1/signup` (เช่น 60 คำขอ/นาที/IP → Block 10 นาที) · **Bot Fight Mode** เปิด
9. **สัปดาห์ละครั้ง**: อื่น ๆ › แฟ้มบันทึกเหตุการณ์ทำงาน › แท็บ การใช้รหัสผ่าน ค้น LOGIN_FAIL — ถ้ามีมากผิดปกติ (รหัสผู้ใช้ที่ไม่มีจริง ผิดติด ๆ กันจำนวนมาก) แจ้งผู้ช่วย หรือเปิดด่านกลับ (ข้อ ข)
10. `wts-buddy.rongphai.workers.dev` เปิดอยู่ด้วย แต่เข้าระบบไม่ได้ (Turnstile ไม่รับชื่อนี้) — ปิดได้ด้วย `"workers_dev": false` ใน wrangler.jsonc ถ้าต้องการ
