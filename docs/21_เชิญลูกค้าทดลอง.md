# เชิญลูกค้าทดลองใช้ Buddy Account (ก่อนเปิดสมัครทั่วไป)

เจ้าของเลือก "เชิญลูกค้าทดลองก่อน" (20/11/2569) — เชิญ 2–5 ราย ด่าน Cloudflare Access ยังเปิดอยู่ ลูกค้าที่เจ้าของใส่อีเมลไว้เท่านั้นที่ผ่านด่านได้

ทำทีละข้อ จบข้อหนึ่งแล้วค่อยทำข้อถัดไป

---

## ก. ก่อนเริ่ม (ทำครั้งเดียว)

1. เข้า https://app.worktruesolution.net ด้วย **รหัสผู้ดูแลระบบที่เจ้าของตั้งตอนตั้งค่าครั้งแรกบนคลาวด์** (ผู้ใช้คนแรกของระบบ = เจ้าหน้าที่ผู้ให้บริการ เห็นทุกลูกค้า)
   - ผู้ใช้ของบริษัทตัวอย่าง (demo.admin, sale1, acc1) **ไม่ใช่** เจ้าหน้าที่ผู้ให้บริการ — อนุมัติใบสมัครไม่ได้
2. เปิด https://app.worktruesolution.net/admin/tenants (เมนู เริ่มระบบ › ลูกค้าผู้ใช้บริการ) — เห็นแผง "ใบสมัครใช้งาน" ด้านบน = ใช้ได้

## ข. เพิ่มอีเมลลูกค้าในด่าน Cloudflare Access (ทุกครั้งที่เชิญลูกค้าใหม่)

1. เปิด https://one.dash.cloudflare.com/
2. เลือกบัญชี → **Zero Trust › Access controls › Applications**
3. คลิกแอป **wts-buddy - Cloudflare Workers** (ปลายทาง `wts-buddy` — ไม่ใช่ buddyapp ซึ่งเป็นทางเข้าเก่าไปเครื่องสำนักงาน) → แท็บ **Policies**
4. **ห้ามแก้นโยบาย "Thaweechai Sanguanjai"** — ใช้ร่วมกับ POS / Living / wts ใส่อีเมลลูกค้าตรงนั้น = ลูกค้าผ่านด่านโปรแกรมอื่นด้วย
5. ครั้งแรก (ทำแล้ว 20/11/2569): **Create new policy** ชื่อ `Buddy trial customers` · Action **Allow** · Session 24 hours · Include **Emails** → Save → อยู่เป็นแถวที่ 2 ของแอป wts-buddy → **Save** หน้าแอป
6. ครั้งต่อไป: คลิกนโยบาย **Buddy trial customers** → **Edit** → เพิ่มอีเมลในช่อง Include › Emails → **Save** (ผูกกับแอป wts-buddy อย่างเดียว)
7. แจ้งลูกค้า: เปิดลิงก์แล้วจะมีหน้าขอรหัสทางอีเมลของ Cloudflare — กรอกอีเมลที่แจ้งไว้ แล้วนำรหัส 6 หลักจากอีเมลมาใส่

## ค. ส่งลิงก์ให้ลูกค้า (ลูกค้าทำเอง)

ส่งข้อความนี้ให้ลูกค้า:

> 1. เปิด https://app.worktruesolution.net/signup
> 2. ใส่อีเมลของคุณที่หน้า Cloudflare แล้วใส่รหัส 6 หลักที่ได้ทางอีเมล
> 3. กรอกใบสมัคร: ชื่อกิจการ (เป็นชื่อบริษัทแรก) · เลขประจำตัวผู้เสียภาษี (ถ้ามี) · ชื่อ อีเมล โทรศัพท์ · รหัสผู้ใช้ · รหัสผ่าน → ติ๊กยอมรับเงื่อนไข → **ส่งใบสมัคร**
> 4. รอผู้ให้บริการแจ้งว่าอนุมัติแล้ว จากนั้นเข้าระบบที่ https://app.worktruesolution.net ด้วยรหัสผู้ใช้และรหัสผ่านที่ตั้งไว้

## ง. อนุมัติใบสมัคร (เจ้าของ)

1. เปิด https://app.worktruesolution.net/admin/tenants
2. แผง "ใบสมัครใช้งาน" → แถวของลูกค้า → ปุ่ม **อนุมัติ…**
3. ใส่ **หมดอายุ** = วันสิ้นสุดทดลอง (เช่น อีก 30 วัน) · ช่องอื่นเว้นว่างได้
4. ช่อง **บริษัทแรก** ติ๊กไว้ (ค่าเริ่มต้น) — ระบบสร้างบริษัทชื่อตามใบสมัคร พร้อมผังบัญชีมาตรฐาน ประเภทเอกสาร รอบบัญชีปีนี้ และการลงบัญชีอัตโนมัติ
5. กด **อนุมัติและเปิดบัญชี**
6. แจ้งลูกค้า: "อนุมัติแล้ว เข้าระบบได้ที่ https://app.worktruesolution.net"
   - ลูกค้าเข้าระบบแล้วเห็นบริษัทของตัวเอง คีย์เอกสารได้ทันที ไม่ต้องให้ผู้ช่วยตั้งค่า
   - ลูกค้าเห็นเฉพาะข้อมูลของตัวเอง เห็นลูกค้ารายอื่นไม่ได้

## จ. ให้ลูกค้าดูข้อมูลตัวอย่างทั้งปี (ดูอย่างเดียว แก้ไม่ได้)

1. เปิด https://app.worktruesolution.net/admin/tenants
2. คลิกแถว **DEMO (ลูกค้าทดลอง บริษัทตัวอย่าง)**
3. เลื่อนลง หัวข้อ "ผู้ใช้ดูอย่างเดียว" → **+ เพิ่มผู้ใช้ดูอย่างเดียว…**
4. ใส่รหัสผู้ใช้เป็นตัวอักษรอังกฤษ (เช่น `demo.shopa`) · ชื่อที่แสดง · รหัสผ่านเริ่มต้น → **เพิ่มผู้ใช้**
5. ส่งรหัสผู้ใช้และรหัสผ่านนี้ให้ลูกค้าทางช่องทางส่วนตัว (LINE/โทร) — หนึ่งรหัสต่อลูกค้าหนึ่งราย
   - ลูกค้าเข้า https://app.worktruesolution.net ด้วยรหัสนี้ = เห็นบริษัทตัวอย่าง เปิดทุกเมนู ดูรายงาน ดูตัวอย่างพิมพ์ทางจอได้
   - ปุ่มบันทึก/ยกเลิก/ลบ กดไม่ได้ · ข้อมูลตัวอย่างไม่เปลี่ยน
   - บริษัทของลูกค้าเอง (ข้อ ง) ยังแก้ไขได้ตามปกติ

## ฉ. จบการทดลอง

1. เปิด https://app.worktruesolution.net/admin/tenants → คลิกแถวลูกค้า
2. ช่อง **สถานะ** เลือก **ระงับ** → **บันทึก** (ผู้ใช้ของลูกค้าถูกออกจากระบบทันที ข้อมูลยังอยู่ — เปลี่ยนกลับเป็น "ใช้งาน" ได้)
   - หรือใส่ **หมดอายุ** ไว้ตั้งแต่ตอนอนุมัติ ระบบปิดให้เองเมื่อเลยวันนั้น
3. ปิดรหัสดูข้อมูลตัวอย่างของลูกค้ารายนั้น: เลือกบริษัท DEMO แล้วเปิด https://app.worktruesolution.net/settings/users → คลิกรหัส `demo.…` ของลูกค้า → สถานะ **ไม่ใช้งาน** → บันทึก
4. เอาอีเมลลูกค้าออกจากด่าน Access (ข้อ ข ขั้น 1–4 แล้วลบอีเมล → Save)
5. ลูกค้าไม่ใช้ต่อและต้องการลบข้อมูล: สถานะ **เลิกใช้** (ระบบเก็บไว้ 90 วันให้ขอสำเนาก่อนลบ ตาม PDPA)


## ช. ก่อนเอาด่าน Cloudflare Access ออก (เปิดให้ทุกคนเข้าหน้าเข้าระบบได้เอง)

ด่าน Access ตอนนี้กันคนนอกไม่ให้เห็นหน้าเข้าระบบเลย — ถ้าจะเอาออก (เจ้าของทำเองที่ Cloudflare Zero Trust · ไม่ใช่งานของโปรแกรม) ให้ครบทุกข้อก่อน:

1. **Turnstile ตั้งแล้วและเห็นกล่องตรวจ** ที่หน้าเข้าระบบและหน้าสมัครใช้งาน — tools/cloud/README ข้อ 12 (เจ้าของสร้าง widget แบบ Managed สำหรับ app.worktruesolution.net แล้วใส่ TURNSTILE_SITE_KEY / TURNSTILE_SECRET เองในแท็บ Terminal)
2. **จำกัดจำนวนครั้งทำงานอยู่** (รุ่น 2569.11.20 ขึ้นไปที่มี HANDOFF 165 — เปิดเองเสมอบนคลาวด์ ไม่ต้องตั้ง) — ลองใส่รหัสผิดหลายครั้งด้วยรหัสผู้ใช้ทดลองจนขึ้น "…บ่อยเกินไป — ลองใหม่ในอีก N นาที"
3. **ทุกผู้ใช้ต้องเปิดยืนยันตัวตนสองขั้น** — รุ่นที่มี HANDOFF 184 บังคับทุกผู้ใช้แล้ว (ผู้ดูแล พนักงาน ผู้ใช้ดูอย่างเดียว เจ้าหน้าที่ผู้ให้บริการ) ผู้ที่ยังไม่ตั้งถูกพาไปหน้าตั้งค่าตอนเข้าระบบ · พนักงานใหม่เชิญด้วยลิงก์ส่งทาง LINE (ผู้ใช้งานระบบ › เพิ่มผู้ใช้ › ให้ผู้ใช้ตั้งรหัสผ่านเองจากลิงก์เชิญ) — ขั้นตอนเอาด่านออกทีละข้อ: tools/cloud/README ข้อ 13
4. **รหัสผ่านไม่ง่าย** — โปรแกรมบังคับ ≥ 8 ตัว มีตัวอักษรและตัวเลขอยู่แล้ว · ลบ/ระงับรหัสทดลองที่ไม่ใช้แล้ว (เช่น ผู้ใช้ดูอย่างเดียวที่หมดการทดลอง ข้อ ฉ)
5. **การสมัครใช้งาน** ยังเป็น **รออนุมัติ** (BUDDY_SIGNUP=review ค่าเริ่มต้น) — อย่าเปลี่ยนเป็นเปิดบัญชีทันที (auto) ถ้าไม่ได้ตั้งใจ
6. **ชื่อ buddy-api ยังมีด่านกุญแจ API** (worker.js gates) — ไม่เกี่ยวกับด่าน Access ของหน้าจอ แต่ตรวจว่าไม่ได้เอาออกพร้อมกัน
7. **ตัวเฝ้าระบบ** (README ข้อ 11) ทำงานอยู่ — ถ้าถูกโจมตีจนโปรแกรมช้า/ล่ม จะได้อีเมล
8. แนะนำเพิ่ม (ตั้งที่ Cloudflare › worktruesolution.net): **WAF Rate limiting rule** สำหรับ `/api/v1/auth/` และ `/api/v1/signup` (เช่น 60 คำขอ/นาที/IP → Block 10 นาที) เป็นชั้นนอกอีกชั้น · **Bot Fight Mode** เปิด
9. หลังเอาด่านออก 1–2 วัน: ดู อื่น ๆ › แฟ้มบันทึกเหตุการณ์ทำงาน ค้น LOGIN_FAIL — ถ้ามีมากผิดปกติจากรหัสผู้ใช้ที่ไม่มีจริง แจ้งผู้ช่วยปรับตัวเลขการจำกัด
